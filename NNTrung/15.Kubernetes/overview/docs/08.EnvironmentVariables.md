# Environment Variables 
## 1. Khái niệm
Environment variables là các biến hệ thống được inject vào process của container tại runtime, giúp truyền thông tin động như credentials, config values, hoặc metadata cluster mà không hardcore vào code ứng dụng.
Trong Kubernetes, env vars được định nghĩa trong `spec.containers[].env` của Pod, và chúng override bất kỳ env vars nào trong container image.

Advantages:
- **Tách biệt config khỏi code**: Dễ thay đổi mà không rebuild image
- **Dynamic values**: Sử dụng downward API để lấy metadata như Pod name, IP, hoặc node info.
- **Integration**: Kết hợp với ConfigMap/Secret để inject data an toàn.
- **Portability**: Ứng dụng có thể chạy ở nhiều môi trường (dev, prod) với env vars khác nhau.

Nguồn env vars trong Kubernetes:
- **Hardcoded values**: Giá trị tĩnh trong YAML
- **ConfigMap/Secret**: Tham chiếu key từ objects này.
- **Downward API**: Metadata từ Pod/fieldRef hoặc resourceFieldRef (ví dụ: CPU limits).
- **Container image**: Env vars mặc định từ Dockerfile, nhưng có thể override.

Nếu có xung đột, env vars từ Pod spec ưu tiên cao nhất. Env vars là string, nhưng ứng dụng có thể parse chúng thành number/boolean.

| Nguồn | Mô tả | Ví dụ YAML | Ưu điểm |
|-------|-------|------------|----------|
| **Value tĩnh** | Gán trực tiếp giá trị trong Pod/Deployment YAML. | `value: "value"` | Đơn giản, nhanh, phù hợp với các giá trị cố định. |
| **ConfigMapKeyRef** | Tham chiếu một key cụ thể từ ConfigMap. | `configMapKeyRef: { name: cm, key: k }` | Quản lý cấu hình không nhạy cảm, dễ cập nhật mà không cần sửa image. |
| **SecretKeyRef** | Tham chiếu một key cụ thể từ Secret. | `secretKeyRef: { name: sec, key: pass }` | Lưu trữ dữ liệu nhạy cảm (mật khẩu, token, API key) an toàn hơn ConfigMap. |
| **FieldRef (Downward API)** | Lấy metadata của Pod hoặc các field do Kubernetes cung cấp. | `fieldRef: { fieldPath: metadata.name }` | Cung cấp thông tin động như Pod name, Pod IP, Namespace, Node name,... |
| **ResourceFieldRef** | Lấy thông tin về resource requests/limits của container. | `resourceFieldRef: { resource: limits.cpu }` | Giúp ứng dụng biết giới hạn CPU/Memory để tự tối ưu hoạt động. |
| **EnvFrom** | Import toàn bộ các key trong ConfigMap hoặc Secret thành environment variables. | `envFrom: [{ configMapRef: { name: cm } }]` | Import hàng loạt biến môi trường, hỗ trợ `prefix` để tránh trùng tên biến. |

## 2. Command và Args
Command và args dùng để override entrypoint (command) và arguments (args) mặc định của container image. Trong Dockerfile, entrypoint là lệnh chính, args là tham số truyền vào.

Trong Kubernetes:
- **Command**: Mảng string thay thế ENTRYPOINT của image
- **Args**: Mảng string thay thế CMD của image
- Nếu không định nghĩa dùng mặc định từ image
- Còn 1 cái nữa là Arg của docker(phân biệt)
  - ARG tồn tại trong quá trình build image, cmd dùng khi chạy container.
  - arg chỉ tồn tại trong quá trình build, cmd tồn tại khi run. Ví dụ người ta thường `arg version=22` và `cmd ["sleep","3600"]`

Advantage:
- **Tùy chỉnh runtime**: Chạy script cụ thể hoặc thay đổi behavior mà không rebuild.
- **Debug**: Chạy shell thay vì app chính để troubleshoot.
- **Bestpractice**: Sử dụng cho Jobs hoặc Pods one-off.

## 3. YAML file
### 3.1 Environment Variables trong YAMl
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: env-pod
spec:
  containers:
  - name: my-container
    image: busybox
    env:  # Mảng các env var
    - name: STATIC_VAR  # Tên biến (uppercase convention)
      value: "hello world"  # Giá trị tĩnh
    - name: CONFIG_VAR
      valueFrom:
        configMapKeyRef:  # Từ ConfigMap
          name: my-configmap
          key: app.key
          optional: false  # Default false, error nếu không tồn tại
    - name: SECRET_VAR
      valueFrom:
        secretKeyRef:  # Từ Secret
          name: my-secret
          key: password
    - name: POD_NAME  # Downward API
      valueFrom:
        fieldRef:
          fieldPath: metadata.name  # Các field: metadata.name, status.podIP, spec.nodeName, etc.
    - name: CPU_LIMIT  # Resource field
      valueFrom:
        resourceFieldRef:
          containerName: my-container  # Optional
          resource: limits.cpu
    envFrom:  # Inject toàn bộ ConfigMap/Secret làm env vars (prefix optional)
    - configMapRef:
        name: my-configmap
    - secretRef:
        name: my-secret
        prefix: DB_  # Optional, prefix keys
```
Lưu ý: `envFrom` inject tất cả keys làm env vars (key thành uppercase, thay – bằng _). Sử dụng cho nhiều vars.

- `valueFrom`: lấy giá trị từ nguồn khác
- `configMapKeyRef`: từ configmap
  - tên config map
  - key muốn lấy làm environment variables. ví dụ trong my-config, app.key= 8080 thì CONFIG_VAR=8080.
  - `fieldRef`: lưu thông tin của chính Pod này rồi đưa vào thành environment variable.
  - `resouceFieldRef`: lấy resource của Container
  - `envFrom`: lấy toàn bộ Key
    - `configMapRef`: toàn bộ config map
    - `secretRef`: toàn bộ secret key


### 3.2 Command và Args 
```yaml
spec:
  containers:
  - name: my-container
    image: alpine
    command: ["/bin/sh"]  # Override ENTRYPOINT
    args: ["-c", "echo $MY_VAR && sleep 60"]  # Override CMD, có thể dùng env vars
```
- Command và args là mảng string để tránh shell parsing issues.

## 4. Các lệnh làm việc
- **Tạo Pod với env vars (imperative)**: `kubectl run env-pod --image=busybox --env="KEY=value" --command -- sleep infinity`
- **Xem env vars trong Pod**: `kubectl exec env-pod -- env`: liệt kê tất cả env
- **Xem env trong spec**: `kubectl describe pod env-pod`
- **edit Pod**: `kubectl edit pod env-pod`
- **Generate YAML**: `kubectl run --dry-run=client -o yaml --env="KEY=val" --command -- echo hello > pod.yaml


## 4.2 Lab 
### 4.2.1 Tạo ConfigMap/Secret cho env
```bash
kubectl create configmap app-config --from-literal=APP_MODE=prod
kubectl create secret generic app-secret --from-literal=API_KEY=secret123
```

### 4.2.2 Tạo Pod YAML với env và command/args: Tạo file `env-command-pod.yaml`:
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: env-command-pod
spec:
  containers:
  - name: busybox
    image: busybox
    command: ["/bin/sh"]
    args: ["-c", "echo MODE: $APP_MODE; echo KEY: $API_KEY; echo POD: $POD_NAME; sleep 3600"]
    env:
    - name: POD_NAME
      valueFrom:
        fieldRef:
          fieldPath: metadata.name
    envFrom:
    - configMapRef:
        name: app-config
    - secretRef:
        name: app-secret
```
- Áp dụng: `kubectl apply -f env-command-pod.yaml`
### 4.2.3 Check
```bash
kubectl get pods
kubectl logs env-command-pod
kubectl exec -it env-command-pod -- env | grep APP
```
### 4.2.4 Clean up
```bash
kubectl delete pod env-command-pod
kubectl delete cm app-config
kubectl delete secret app-secret
```
