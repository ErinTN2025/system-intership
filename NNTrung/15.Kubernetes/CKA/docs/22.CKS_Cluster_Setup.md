# CKS: cluster setup security (roadmap tuần 13)

## Lý thuyết cốt lõi

Hardening bắt đầu từ inventory và exposure: API server endpoint, kubelet API, etcd, ingress và node network. CIS Benchmark là tập kiểm tra cấu hình theo phiên bản, không phải lệnh sửa tự động; phải đối chiếu từng finding với topology và phiên bản cluster. TLS bảo vệ đường truyền, RBAC bảo vệ quyền API, NetworkPolicy bảo vệ đường mạng Pod; chúng giải quyết các lớp khác nhau.

## Lab A: audit cấu hình cluster

**Môi trường:** VM kubeadm riêng. Chạy kube-bench với profile phù hợp phiên bản Kubernetes; lưu report, chọn ba finding thật có thể tái hiện. Kiểm tra flags API server bằng manifest static Pod, cổng đang listen bằng `ss -lntp`, anonymous auth và authorization mode theo tài liệu hiện hành. Trước khi sửa manifest, lưu bản sao ngoài thư mục `/etc/kubernetes/manifests` (kubelet có thể đọc file backup trong đó như một manifest). Sửa một finding có kiểm soát, xác nhận API server lên lại và chạy lại đúng kiểm tra.

## Lab B: TLS và kiểm tra binary

Trên namespace thử, tạo TLS Secret bằng chứng chỉ tự ký **chỉ cho lab**; cấu hình Ingress TLS nếu đã có controller; dùng `openssl s_client` kiểm tra chứng chỉ được phục vụ. Tải một binary từ nguồn chính thức và kiểm tra SHA256/signature theo đúng tài liệu release; cố ý đổi một byte của bản sao để chứng minh checksum fail. Không lưu private key trong Git.

**Đạt khi:** report có `finding → nguyên nhân → thay đổi → bằng chứng kiểm tra lại`; phân biệt được API exposure với Ingress exposure. Xem [nguồn CIS/cluster security](29.Tai_lieu_tham_khao.md#cks-và-kcsa-security).
