# CKS: network segmentation và Secret (roadmap tuần 16)

## Lý thuyết cốt lõi

NetworkPolicy chọn Pod đích bằng `podSelector`; một kết nối được phép khi policy ingress của đích **và** egress của nguồn cho phép. Default-deny egress cũng chặn DNS nếu không mở. Policy chỉ có tác dụng khi CNI implementation hỗ trợ. Namespace isolation cần nhãn namespace/Pod có chủ đích. Secret mặc định là API object được base64 encode, không đồng nghĩa mã hóa ở etcd; encryption at rest cần cấu hình API server/provider. External secrets và Secrets Store CSI Driver liên quan vòng đời Secret bên ngoài, khác CSI lưu trữ PV.

## Lab A: ứng dụng ba tầng

**Môi trường:** cluster có NetworkPolicy enforcement. Tạo namespace và ba Deployment `frontend`, `backend`, `db`, cùng Service nội bộ; dùng image có công cụ HTTP/TCP phù hợp. Xác nhận ban đầu frontend gọi backend/db được. Tạo default-deny ingress+egress cho cả namespace; kiểm tra cả kết nối hợp lệ lẫn không hợp lệ đều fail. Thêm policy cho DNS egress tới CoreDNS/kube-dns; thêm egress frontend→backend và ingress backend←frontend; thêm egress backend→db và ingress db←backend. Kiểm tra frontend→backend, backend→db thành công; frontend→db và db→frontend thất bại. Nếu DNS vẫn lỗi, xác minh label/namespace của DNS Pod trước khi chỉnh selector.

## Lab B: Secret at rest

Trên VM kubeadm snapshot, đọc cấu hình API server để xem encryption provider có bật không. Theo tài liệu chính thức, tạo `EncryptionConfiguration` với key lab, gắn `--encryption-provider-config` vào API server; kiểm tra API lên lại. Tạo Secret thử **sau khi bật**, đọc trực tiếp record etcd bằng client TLS và xác nhận prefix ciphertext; dùng `kubectl get secret` xác nhận ứng dụng vẫn đọc được. Không in giá trị thật, dùng chuỗi giả. Thử rotation theo tài liệu nếu đủ thời gian; giữ bản backup key vì mất key có thể làm Secret không đọc được.

**Đạt khi:** bảng kết quả kết nối 4 chiều đúng mong đợi, giải thích được vì sao NetworkPolicy không bảo vệ dữ liệu trong etcd; Secret thử được mã hóa ở tầng API. Xem [nguồn network/encryption](29.Tai_lieu_tham_khao.md#cks-và-kcsa-security).
