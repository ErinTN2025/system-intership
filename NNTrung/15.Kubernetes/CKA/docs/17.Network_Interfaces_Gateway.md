# CRI, CNI, CSI, CCM và Gateway API (roadmap tuần 9)

## Lý thuyết cốt lõi

**CRI** là giao diện kubelet ↔ runtime; **CNI** cấu hình network namespace/IP của Pod; **CSI** đưa storage provider vào Kubernetes; **CCM** tách tích hợp cloud (node, route, load balancer) khỏi core. Chúng là các interface/điểm tích hợp khác nhau, không phải bốn tiến trình bắt buộc luôn có cùng tên. Gateway API dùng `GatewayClass` (implementation), `Gateway` (listener) và `HTTPRoute` (quy tắc route); chỉ cài CRD chưa có traffic nếu thiếu controller thực thi.

## Lab A: lần theo interface trên cluster kubeadm

Trên worker: `sudo crictl info`, `sudo crictl pods`, xem `/etc/cni/net.d`, interface/route qua `ip addr` và `ip route`; trong cluster: `kubectl -n kube-system get ds,pods`, `kubectl get csidrivers,storageclasses`. Tạo Pod thử rồi so Pod UID/IP trên API với sandbox trong `crictl`; ghi CNI plugin đang dùng. Nếu cluster local không có CCM, mô tả việc `Service.type=LoadBalancer` có/không được cấp external IP và vì sao. Không tự cài CCM cloud vào cluster local chỉ để có output.

## Lab B: HTTPRoute

**Môi trường:** cluster lab có Gateway API CRD và một implementation tương thích; chọn và cài theo [Getting started của Gateway API](https://gateway-api.sigs.k8s.io/guides/getting-started/) và tài liệu implementation. Kiểm tra `kubectl get gatewayclass`, controller Pod Ready. Tạo hai Service `web-a`, `web-b` (mỗi Service trỏ Deployment khác nhau); tạo Gateway listener HTTP port 80 và HTTPRoute có hai rule `/a` → `web-a`, `/b` → `web-b`. Kiểm tra `kubectl describe httproute`, status `Accepted=True`, `ResolvedRefs=True`; gửi request tới địa chỉ Gateway với đúng hostname/path và đối chiếu response.

**Failure injection:** đổi `backendRefs.name` sang Service không tồn tại; xem condition `ResolvedRefs=False`, sửa lại và xác minh. So trách nhiệm GatewayClass/Gateway/HTTPRoute với Ingress/Ingress Controller. **Đạt khi:** xác định được implementation thực sự xử lý route, không chỉ CRD tồn tại.
