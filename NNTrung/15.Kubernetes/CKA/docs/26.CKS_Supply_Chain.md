# CKS: image supply chain (roadmap tuần 17)

## Lý thuyết cốt lõi

Một image tag có thể trỏ sang digest khác; digest định danh nội dung bất biến. Scan tìm lỗ hổng đã biết và misconfiguration, SBOM liệt kê thành phần, chữ ký chứng minh ai đã ký digest, provenance mô tả nguồn/quy trình build. Không biện pháp nào tự chứng minh ứng dụng an toàn. Luồng cần thực hành: build → scan → SBOM → sign → verify → deploy bằng digest; policy admission có thể từ chối image không đạt tiêu chí.

## Lab: pipeline mẫu trên registry thử

**Môi trường:** registry lab mà bạn có quyền push, Docker/BuildKit hoặc tương đương, Trivy, Syft, Cosign theo tài liệu phiên bản hiện hành. Tạo ứng dụng HTTP nhỏ, multi-stage Dockerfile, user non-root và base image cố định. Build, push, ghi digest từ registry; chạy `trivy image <IMAGE@DIGEST>`, `syft <IMAGE@DIGEST> -o spdx-json > sbom.json`. Phân tích ít nhất một finding: package nào, version nào, fix version có hay không. Không công bố `sbom.json` nếu chứa thông tin nội bộ.

Ký **digest** bằng Cosign theo mô hình keyless hoặc key pair lab; ghi rõ identity/issuer hoặc public key dùng để verify. `cosign verify <IMAGE@DIGEST>` phải pass; verify một digest khác phải fail. Deploy Kubernetes manifest dùng `image: <IMAGE@DIGEST>`; kiểm tra `imageID` của Pod. Chạy linter manifest (Trivy config hoặc KubeLinter), sửa một vấn đề thật (ví dụ thiếu `runAsNonRoot`). Nếu triển khai registry policy, thử image hợp lệ và image không hợp lệ qua server dry-run; chỉ làm trên cluster lab.

**Đạt khi:** có log build/scan/SBOM/sign/verify/deploy và giải thích được khác nhau giữa tag, digest, chữ ký và SBOM. Không commit khóa ký riêng hoặc token registry. Xem [nguồn supply chain](29.Tai_lieu_tham_khao.md#cks-và-kcsa-security).
