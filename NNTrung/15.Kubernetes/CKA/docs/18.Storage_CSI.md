# Storage, PV/PVC và CSI nâng cao (roadmap tuần 9)

## Lý thuyết cốt lõi

PVC là yêu cầu storage; PV là volume đáp ứng; StorageClass chọn provisioner, binding mode, reclaim policy và các tham số. `Immediate` bind/provision ngay; `WaitForFirstConsumer` chờ Pod để biết topology phù hợp. CSI gồm controller và node plugin, có thể kèm external provisioner/attacher/resizer/snapshotter. `VolumeSnapshot` cần CRD/controller/driver hỗ trợ; PVC Pending không mặc nhiên là lỗi CSI.

## Lab: lần theo vòng đời volume

**Môi trường:** cluster có StorageClass hoạt động; kiểm tra `kubectl get sc -o wide` và tên provisioner. Tạo namespace `storage-lab`. Thay `<STORAGE_CLASS>` bằng tên class thực tế rồi apply manifest sau:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: data
  namespace: storage-lab
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: <STORAGE_CLASS>
  resources:
    requests:
      storage: 1Gi
---
apiVersion: v1
kind: Pod
metadata:
  name: writer
  namespace: storage-lab
spec:
  containers:
  - name: writer
    image: busybox:1.36
    command: [sh, -c, 'echo persistent > /data/check; sleep 3600']
    volumeMounts:
    - name: data
      mountPath: /data
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: data
```

Nếu class dùng `WaitForFirstConsumer`, PVC có thể Pending cho đến khi Pod được lập lịch. Quan sát:

```bash
kubectl -n storage-lab get pvc,pod -o wide
kubectl get pv
kubectl -n storage-lab describe pvc data
kubectl -n storage-lab describe pod writer
kubectl get csidrivers,csinodes
```

Xóa Pod, tạo Pod khác dùng cùng PVC, xác nhận `/data/check` còn tồn tại. Xem PV `reclaimPolicy`, `nodeAffinity` và Events. Nếu driver hỗ trợ expansion, tăng request PVC và xác nhận capacity; nếu không, ghi rõ capability thiếu. Nếu cài snapshot controller và driver hỗ trợ snapshot, tạo `VolumeSnapshotClass`/`VolumeSnapshot`, restore vào PVC mới; không giả định mọi local provisioner hỗ trợ snapshot.

**Failure injection:** tạo PVC tham chiếu StorageClass không tồn tại; xem PVC Pending và Events, sửa class bằng cách tạo PVC mới vì một số trường PVC không sửa được. **Đạt khi:** vẽ được đường PVC → StorageClass → PV → CSI provisioner/node mount; phân biệt `Pending` do class không tồn tại với mount lỗi. **Dọn:** xóa namespace, kiểm tra PV còn tồn tại theo reclaim policy; chỉ xóa volume lab của chính mình.
