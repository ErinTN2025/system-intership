# Tự xây CRD và controller tối giản (roadmap tuần 11)

## Lý thuyết cốt lõi

CRD tạo API; controller hiện thực hóa desired state. `metadata.generation` tăng khi spec đổi; controller ghi `status.observedGeneration` sau khi xử lý. `conditions` giúp phân biệt Accepted/Ready/Failed. OwnerReference cho phép garbage collection object con; finalizer cho controller cơ hội cleanup trước khi object biến mất. Reconcile phải idempotent: chạy lại nhiều lần vẫn dẫn tới cùng trạng thái. [Lab Operator có sẵn](09.CRD_Operator.md) là phần tiền đề.

## Lab A: CRD WebApp

Tạo CRD namespaced `webapps.lab.example.com`, group `lab.example.com`, version `v1alpha1`, schema OpenAPI v3 với `spec.image` (string, required), `spec.replicas` (integer, minimum 1), `status.observedGeneration` (integer), `status.conditions` (array); bật `subresources.status`. Bản tối thiểu để bắt đầu:

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: webapps.lab.example.com
spec:
  group: lab.example.com
  scope: Namespaced
  names:
    plural: webapps
    singular: webapp
    kind: WebApp
    shortNames: [wa]
  versions:
  - name: v1alpha1
    served: true
    storage: true
    subresources:
      status: {}
    schema:
      openAPIV3Schema:
        type: object
        properties:
          spec:
            type: object
            required: [image]
            properties:
              image:
                type: string
                minLength: 1
              replicas:
                type: integer
                minimum: 1
                default: 1
          status:
            type: object
            properties:
              observedGeneration:
                type: integer
              conditions:
                type: array
                x-kubernetes-list-type: map
                x-kubernetes-list-map-keys: [type]
                items:
                  type: object
                  required: [type, status, lastTransitionTime, reason, message]
                  properties:
                    type: {type: string}
                    status: {type: string}
                    lastTransitionTime: {type: string, format: date-time}
                    reason: {type: string}
                    message: {type: string}
```

Lưu thành `webapp-crd.yaml`, chạy `kubectl apply -f webapp-crd.yaml`, `kubectl wait --for=condition=Established crd/webapps.lab.example.com`, `kubectl api-resources --api-group=lab.example.com`, `kubectl explain webapp.spec`. Tạo CR hợp lệ với `spec.image: nginx:1.27`; thử CR thiếu `image` hoặc `replicas: 0` bằng `kubectl apply --dry-run=server -f ...` và ghi thông báo validation. Chỉ dùng domain `lab.example.com` trong cluster thực hành. CRD ở đây chỉ có một version; versioning/conversion là bài mở rộng sau khi controller cơ bản chạy tốt.

## Lab B: controller

Chọn **Kubebuilder** hoặc **Kopf** theo ngôn ngữ bạn quen, bám quickstart đúng phiên bản tool trong [nguồn](29.Tai_lieu_tham_khao.md#api-extension-và-operator). Viết reconcile cho `WebApp`: đọc CR, tạo/cập nhật Deployment và Service mang ownerReference, chỉ update khi khác desired state, cập nhật status/conditions; thêm finalizer để ghi một ConfigMap audit khi xóa (mô phỏng cleanup, không gọi dịch vụ ngoài). Cấp RBAC tối thiểu cho webapps, deployments, services, status/finalizers; cài controller vào namespace lab.

**Thử nghiệm:** (1) đổi `spec.replicas` và thấy Deployment đổi; (2) xóa Deployment con và thấy được tạo lại; (3) tạo CR sai schema bị API từ chối; (4) xóa CR và thấy finalizer hoàn tất, object con bị garbage collect; (5) restart controller giữa reconcile và xác nhận không nhân đôi resource. Xem `status.observedGeneration` bằng generation mới. **Đạt khi:** giải thích rõ trường hợp CRD có nhưng controller dừng: CR vẫn lưu được, workload không được reconcile. **Dọn:** xóa CR, controller/RBAC, rồi CRD sau cùng trên cluster lab riêng.
