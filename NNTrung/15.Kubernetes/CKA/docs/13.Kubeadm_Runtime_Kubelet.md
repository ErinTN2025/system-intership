# Kubeadm, containerd và kubelet (roadmap tuần 5)

## Lý thuyết cốt lõi

`kubeadm` khởi tạo thành phần control plane và cấu hình join; `kubelet` là agent trên từng node; containerd chạy container qua CRI; CNI cấp kết nối mạng cho Pod. Kubelet đọc static Pod manifest tại `/etc/kubernetes/manifests`, gửi trạng thái node/Pod về API server và gọi CRI để tạo Pod sandbox. `crictl` quan sát runtime ngay cả khi API server lỗi. Node `NotReady` có thể do kubelet, runtime hoặc CNI; kiểm tra theo thứ tự service → journal → runtime → network.

## Lab: cluster 1 control plane + 1 worker

**Môi trường:** hai VM Linux riêng, snapshot trước lab, quyền root. Chọn cùng Kubernetes minor version cho gói cài và tài liệu; xem hướng dẫn cài containerd, kubeadm và CNI tương ứng bản đó trong [nguồn](29.Tai_lieu_tham_khao.md). Cấu hình swap, kernel/sysctl, cgroup driver theo hướng dẫn chính thức, không sao chép lệnh cũ từ blog. Ghi lại địa chỉ IP node, Pod CIDR và CNI tương thích trước khi `init`.

1. Trên mỗi VM: cài containerd, `kubelet`, `kubeadm`; chỉ cần `kubectl` trên máy quản trị. Xác nhận `systemctl status containerd kubelet` và `crictl info`.
2. Trên control plane: `sudo kubeadm init --pod-network-cidr=<CIDR_CUA_CNI>`. Lưu join command vào ghi chú lab, không commit token.
3. Cấu hình kubeconfig của user theo output `kubeadm init`; cài CNI theo tài liệu **phiên bản của plugin** đã chọn. Đợi `kubectl get nodes -o wide` báo Ready.
4. Trên worker: chạy join command; xác nhận hai node Ready, CoreDNS Running.
5. Trên worker: so `crictl pods`, `crictl ps -a`, `journalctl -u kubelet -n 80 --no-pager` với `kubectl get pods -A -o wide`.

**Failure injection:** chỉ trên worker lab, sao lưu `/var/lib/kubelet/config.yaml`, đổi tạm một trường hợp lệ thành giá trị sai để kubelet không khởi động; `systemctl restart kubelet`, xem `systemctl status`, `journalctl -u kubelet`, khôi phục file gốc và restart. Tránh sửa control plane ở bài đầu.

**Đạt khi:** giải thích được kubeadm/kubelet/containerd/CNI khác nhau; worker từ NotReady về Ready; một Pod thử chạy trên worker. **Dọn:** `kubectl drain <worker> --ignore-daemonsets --delete-emptydir-data`, xóa node khỏi cluster, `kubeadm reset` trên worker lab theo tài liệu. Xem [nguồn kubeadm và CRI](29.Tai_lieu_tham_khao.md#cka-cluster-và-control-plane).
