# Kustomize: base, overlay, patch, image transformation
## 0. Đặt vấn đề
Bạn có một app cần chạy ở 3 môi trường: dev, staging, prod. File YAML gần như giống nhau, chỉ khác vài chỗ:

| 	|dev |	prod |
|---|-----|--------|
| số replica |	1 | 	5|
| image tag |	latest	| v1.4.2 |
| RAM |	128Mi|	2Gi|

Cách ngây thơ là chép YAML ra 3 bản rồi sửa từng bản. Sau đó sửa một chỗ chung thì phải sửa 3 nơi, và dễ lệch nhau.

Kustomize giải quyết bằng cách: giữ một bản chung, mỗi môi trường chỉ ghi phần khác biệt, rồi nó ghép lại thành YAML cuối. Nó là kiểu "cho tôi file gốc + danh sách chỉnh sửa", không dùng template như Helm.

```
app/
├── base/                    ← cấu hình CHUNG
│   ├── deployment.yaml
│   ├── service.yaml
│   └── kustomization.yaml
└── overlays/
    ├── dev/                 ← chỉ ghi phần KHÁC của dev
    │   └── kustomization.yaml
    └── prod/                ← chỉ ghi phần KHÁC của prod
        ├── kustomization.yaml
        └── replica-patch.yaml
```
- Base: bản gốc dùng chung. Bạn không sửa nó cho từng môi trường.
- Overlay: lớp phủ lên base. Giống lớp trong Photoshop: base là ảnh nền, overlay chỉ vẽ phần thay đổi chồng lên.

`resources`: "nạp cái gì vào". Nó liệt kê file YAML hoặc thư mục kustomization khác để gom lại. Trong base:

```yaml
# base/kustomization.yaml
resources:
  - deployment.yaml
  - service.yaml
```
Trong overlay thì nạp cả base vào:
```yaml
# overlays/prod/kustomization.yaml
resources:
  - ../../base        # lấy toàn bộ base làm nền
```
`patches`: **"sửa cái gì"**. Sửa một phần resource mà không chép cả file. Ví dụ prod muốn 5 replica:

```yaml
# overlays/prod/kustomization.yaml (tiếp)
patches:
  - path: replica-patch.yaml
    target:
      kind: Deployment
      name: myapp
```
```yaml
# replica-patch.yaml: chỉ ghi chỗ cần đổi
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 5
```
`target`: "nhắm vào ai". Overlay có thể gom nhiều resource, nên cần chỉ rõ patch áp dụng cho resource nào (theo kind, name...). Đó là lý do đoạn bạn đọc dặn "nên chỉ rõ target để tránh sửa nhầm": nếu không, patch có thể rơi vào resource không định sửa.

`images`: "đổi image cho gọn". Thay vì patch cả Deployment chỉ để đổi tag:
```bash
images:
  - name: myapp
    newTag: v1.4.2
```
Đổi tag, tên hoặc digest của image mà không phải đụng tới Deployment gốc.
- Hai lệnh cuối:
```bash
kubectl kustomize overlays/prod     # chỉ in ra YAML cuối để xem, KHÔNG gửi lên cluster
kubectl apply -k overlays/prod      # ghép xong gửi thẳng lên API server
```

## Lý thuyết cốt lõi

Kustomize tạo manifest cuối từ các YAML gốc mà không sửa trực tiếp chúng. **Base** chứa cấu hình chung; **overlay** tham chiếu base và chỉ khai báo khác biệt của môi trường. `resources` nạp manifest hoặc kustomization khác. `patches` sửa một hoặc nhiều resource; nên chỉ rõ `target` để tránh sửa nhầm. `images` thay image name/tag/digest mà không phải chép lại Deployment. `kubectl kustomize <dir>` chỉ render; `kubectl apply -k <dir>` gửi kết quả lên API server. Kustomize tích hợp trong `kubectl` có thể khác phiên bản CLI độc lập.

## Lab: dựng base và overlay

Yêu cầu: shell Bash và `kubectl`. Tạo cây thư mục:

```text
kustomize-lab/
  base/{deployment.yaml,service.yaml,kustomization.yaml}
  overlays/dev/kustomization.yaml
  overlays/prod/{kustomization.yaml,replicas.yaml}
```

```bash
mkdir -p kustomize-lab/base kustomize-lab/overlays/dev kustomize-lab/overlays/prod
cat > kustomize-lab/base/deployment.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 1
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
EOF
cat > kustomize-lab/base/service.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
EOF
cat > kustomize-lab/base/kustomization.yaml <<'EOF'
resources:
- deployment.yaml
- service.yaml
EOF
cat > kustomize-lab/overlays/dev/kustomization.yaml <<'EOF'
resources:
- ../../base
namespace: kustomize-dev
nameSuffix: -dev
images:
- name: nginx
  newTag: '1.27'
EOF
cat > kustomize-lab/overlays/prod/replicas.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
EOF
cat > kustomize-lab/overlays/prod/kustomization.yaml <<'EOF'
resources:
- ../../base
namespace: kustomize-prod
nameSuffix: -prod
images:
- name: nginx
  newTag: '1.27'
patches:
- path: replicas.yaml
  target:
    group: apps
    version: v1
    kind: Deployment
    name: web
EOF
kubectl kustomize kustomize-lab/overlays/dev
kubectl kustomize kustomize-lab/overlays/prod
```

Trong output, dev có `web-dev`, 1 replica và nginx `1.27`; prod có `web-prod`, 3 replica và cùng image. Kiểm tra Service selector vẫn trỏ vào Pod labels. Tạo namespace trước khi apply vì trường `namespace` không tự tạo Namespace:

```bash
kubectl create namespace kustomize-dev
kubectl create namespace kustomize-prod
kubectl apply -k kustomize-lab/overlays/dev
kubectl apply -k kustomize-lab/overlays/prod
kubectl -n kustomize-prod rollout status deployment/web-prod
kubectl -n kustomize-prod get deployment web-prod -o jsonpath='{.spec.replicas}{"\n"}{.spec.template.spec.containers[0].image}{"\n"}'
```

Nếu `kubectl kustomize` báo patch không khớp, kiểm tra `group/version/kind/name` của resource **trước** khi áp `nameSuffix`. Nếu Pod không nhận lưu lượng, so `Service.spec.selector` với `Deployment.spec.template.metadata.labels` của bản đã render.
