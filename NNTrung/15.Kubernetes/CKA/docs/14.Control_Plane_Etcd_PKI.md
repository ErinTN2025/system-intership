# Control plane, PKI và etcd (roadmap tuần 6)

## Lý thuyết cốt lõi

API server là điểm vào của Kubernetes API; scheduler chọn node cho Pod chưa được gán; controller manager chạy các control loop; etcd lưu trạng thái API. kubeadm thường triển khai các thành phần control plane thành static Pod. Certificate xác thực danh tính giữa các thành phần; kubeconfig chứa endpoint, CA và thông tin đăng nhập. etcd cần quorum để ghi; cluster một member chỉ phù hợp lab. Snapshot etcd phải đi cùng bài **restore và xác minh dữ liệu**, vì file snapshot riêng chưa chứng minh khôi phục được.

## Lab A: lần theo một request

**Môi trường:** cluster kubeadm riêng từ bài 13. Tạo namespace `control-lab` và ConfigMap `marker` có key `version=before`. Quan sát lần lượt:

```bash
kubectl get --raw /readyz?verbose
kubectl -n kube-system get pods -o wide
kubectl -n control-lab get configmap marker -o yaml
sudo ls /etc/kubernetes/manifests
sudo kubeadm certs check-expiration
```

Trên control plane, xem các manifest static Pod và vị trí các `--client-ca-file`, `--etcd-*`, kubeconfig component. Vẽ luồng `kubectl → API server → authentication/authorization/admission → etcd → watch → controller/kubelet`. Không sao chép private key/kubeconfig vào repository.

## Lab B: snapshot và restore có kiểm chứng

1. Xem `/etc/kubernetes/manifests/etcd.yaml` để xác định endpoint, CA, client certificate/key và data dir **của cluster này**.
2. Dùng `etcdctl --endpoints=<ENDPOINT> --cacert=<CA> --cert=<CERT> --key=<KEY> endpoint health` và `snapshot save /root/etcd-lab.db` trên control plane. Chạy `etcdutl snapshot status /root/etcd-lab.db`.
3. Đổi ConfigMap `marker` thành `version=after` rồi xác nhận API thấy `after`.
4. Theo [quy trình restore chính thức](https://kubernetes.io/docs/tasks/administer-cluster/configure-upgrade-etcd/), dùng `etcdutl snapshot restore` vào **data dir mới**, cập nhật hostPath của static Pod etcd tới dir mới, chờ API server trở lại. Không ghi đè data dir cũ khi chưa có snapshot VM và kế hoạch quay lại.
5. Xác nhận ConfigMap trở về `before`, node Ready, CoreDNS/Pod thử hoạt động. Trả lại cấu hình hoặc phục hồi snapshot VM sau bài lab.

**Failure injection riêng:** sao lưu manifest scheduler trên VM lab, thay một image thành tag sai, xem `crictl ps -a` và `journalctl -u kubelet`; khôi phục manifest rồi xác nhận scheduler Running. **Đạt khi:** tự giải thích được vì sao API mất khả dụng khi etcd lỗi và chứng minh restore bằng dữ liệu `before`. Xem [nguồn etcd/PKI](29.Tai_lieu_tham_khao.md#cka-cluster-và-control-plane).
