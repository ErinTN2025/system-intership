# Đổi riêng Horizon sang OpenStack 2025.2

## 1. Mục đích và phạm vi

Tài liệu này chuẩn bị đổi dashboard Horizon từ image release 2026.1 sang 2025.2. Không hạ phiên bản Keystone, Nova, Neutron, Cinder hoặc Octavia. Chọn 2025.2 (Flamingo) là release cuối năm 2025; nếu muốn 2025.1 phải chọn lại image và plugin tương ứng.

[Thông tin release Horizon](https://releases.openstack.org/teams/horizon.html) và [yêu cầu Horizon 2025.2](https://docs.openstack.org/horizon/2025.2/install/system-requirements.html). Việc Horizon 2025.2 kết nối backend 2026.1 cần được kiểm tra trên lab, chưa được nghiệm thu. Đổi release không tự sửa timeout hoặc bổ sung Octavia Dashboard.

## 3. Lưu cấu hình hiện tại

Chạy trên bastion. Lưu snapshot có ngày giờ để không ghi đè bản trước. Values có thể chứa credentials nên không commit thư mục này lên Git.

```bash
(
set -eu
umask 077
WORK="$HOME/osh-lab/horizon-version/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$WORK"
helm get values horizon -n openstack --all -o yaml > "$WORK/before.yaml"
helm history horizon -n openstack -o json > "$WORK/history.json"
kubectl -n openstack get deployment horizon -o yaml > "$WORK/deployment-before.yaml"
printf 'Snapshot: %s\n' "$WORK"
)
```

Không thay chart version chỉ vì đổi image. Giữ chart đang dùng để giảm số thành phần thay đổi; chart 2026.1 có thể chứa cấu hình khác Horizon 2025.2 nên vẫn phải đối chiếu render và kiểm tra startup.

## 4. Xác minh image đích tồn tại

Image dưới là tên ứng viên theo convention Airship; chưa xác nhận registry thực sự có tag này. Không chạy Helm upgrade trước khi xác minh image và package bên trong.

```bash
command -v docker || true
command -v skopeo || true
```

Nếu có Docker:

```bash
docker manifest inspect quay.io/airshipit/horizon:2025.2-ubuntu_noble
```

Nếu có Skopeo, dùng lệnh này thay cho Docker:

```bash
skopeo inspect docker://quay.io/airshipit/horizon:2025.2-ubuntu_noble
```

`manifest unknown` nghĩa là tag không tồn tại; lỗi DNS hoặc timeout nghĩa là chưa truy cập được registry, không kết luận image không tồn tại. Sau khi xác minh tag, ghi nhận digest và kiểm tra package Horizon, Django, Heat/TaaS/Octavia Dashboard trong image đích trước khi triển khai. Không đoán package version từ image tag.

## 5. Kế hoạch chuyển phiên bản sau khi xác minh image

1. Chọn image 2025.2 đã kiểm tra và pin digest.
2. Giữ cấu hình HTTPS Gateway, CSRF origins, secure cookies và `endpoint_type: internalURL` từ snapshot. Đối chiếu cấu hình này với phiên bản đích.
3. Kiểm tra hai panel hiện tại trong image mới. Nếu thêm Octavia Dashboard, dùng plugin thuộc release 2025.2; Dockerfile ở `images/horizon-octavia` hiện pin plugin 2026.1 nên không dùng nguyên bản cho 2025.2.
4. Trong lần thử này chỉ đổi `images.tags.horizon`, giữ image DB sync hiện tại và dùng `--no-hooks` để không chạy DB Jobs. Không chạy lại DB sync bằng image cũ hoặc mới trước khi đánh giá migrations.
5. Đánh giá migration/session backend Horizon trước khi chạy các DB Jobs. Snapshot Helm không phải backup database; không coi `helm rollback` là thao tác khôi phục schema đã bị thay đổi.
6. Render bằng chart local hiện tại, snapshot và override rồi kiểm tra cấu hình và các Jobs. Chỉ upgrade khi đã giải quyết image/plugin/config/database.
7. Kiểm tra rollout, phiên bản package, đăng nhập HTTPS, danh sách VM/network/volume và LB panel nếu đã bổ sung plugin. Runtime mới đạt Ready chưa chứng minh mọi API backend tương thích.

Hiện mới hoàn thành xác định phiên bản nguồn và chuẩn bị quy trình. Chưa hạ phiên bản, chưa có image đích đã xác minh và chưa nghiệm thu. Lệnh upgrade cuối sẽ được bổ sung sau các bước xác minh, tránh lưu một lệnh copy-paste trỏ tới image chưa tồn tại hoặc tự chạy migration khi downgrade.

## 6. Image 2025.2 đã xác minh và kiểm tra bằng pod tạm

`docker manifest inspect` đã xác nhận tag `quay.io/airshipit/horizon:2025.2-ubuntu_noble` tồn tại. Manifest Linux amd64 có digest `sha256:6c11946d6ac14d0cd0404a1e66c6a194b30a13d46387c0388f772dc759dd8567`. Entry unknown/unknown còn lại không phải image dùng cho node amd64. Chưa xác nhận phiên bản package bên trong hoặc khả năng chạy với cấu hình hiện tại.

Chạy pod tạm trên bastion để đọc package. Pod không mount Secret/database của Horizon và không chạy web server; nó chỉ in thông tin rồi kết thúc. Không cần Docker daemon trên bastion vì kubelet tải image trên node.

```bash
(
set -eu
IMAGE='quay.io/airshipit/horizon@sha256:6c11946d6ac14d0cd0404a1e66c6a194b30a13d46387c0388f772dc759dd8567'
POD="horizon-2025-check-$(date +%s)"
printf 'Probe pod: %s\n' "$POD"
kubectl -n openstack run "$POD" --restart=Never --image="$IMAGE" \
  --command -- python3 -c '
import sys
from importlib.metadata import version, PackageNotFoundError
from importlib.util import find_spec
print("Python:", sys.executable)
for name in ["horizon", "Django", "octavia-dashboard"]:
    try:
        print(name + ":", version(name))
    except PackageNotFoundError:
        print(name + ": NOT INSTALLED")
for name in ["heat_dashboard", "neutron_taas_dashboard", "octavia_dashboard"]:
    print(name + ":", "FOUND" if find_spec(name) else "NOT INSTALLED")
'
if kubectl -n openstack wait --for=jsonpath='{.status.phase}'=Succeeded \
  "pod/$POD" --timeout=180s; then
  kubectl -n openstack logs "$POD"
  kubectl -n openstack delete pod "$POD"
else
  kubectl -n openstack get pod "$POD" -o wide
  kubectl -n openstack logs "$POD" || true
  printf 'Probe chưa thành công; giữ pod để kiểm tra: kubectl -n openstack describe pod %s\n' "$POD"
  exit 1
fi
)
```

Timeout có thể do tải image lâu hoặc scheduling; không đồng nghĩa image lỗi. Đối chiếu output trước khi chọn panel và chuẩn bị override. Nếu pod bị admission policy từ chối, đọc thông báo để sửa probe phù hợp policy; không thay policy của namespace chỉ để chạy kiểm tra.

## 7. Chuyển dashboard sau khi probe thành công

Probe đã chạy thành công: Horizon `25.5.3.dev10`, Django `4.2.23`, Python trong `/var/lib/openstack`. Image không có Heat Dashboard, TaaS Dashboard hoặc Octavia Dashboard. Override dưới đặt `extra_panels: []`; việc này bỏ giao diện plugin trên dashboard, không gỡ các dịch vụ backend. PodSecurity chỉ cảnh báo trong lần probe và không chặn pod.

Chạy trên bastion. Snapshot lần này được lấy ngay trước upgrade; thư mục được in cuối lệnh là nơi lưu cấu hình và rollback revision. Chỉ đổi image dashboard, không chạy Helm hooks và giữ DB sync image hiện tại. Đây là thử nghiệm dashboard 2025.2 với backend 2026.1, chưa nghiệm thu tương thích.

```bash
(
set -eu
umask 077
CHART="$HOME/osh-lab/charts/horizon"
WORK="$HOME/osh-lab/horizon-version/switch-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$WORK"
test -f "$CHART/Chart.yaml"
helm get values horizon -n openstack --all -o yaml > "$WORK/before.yaml"
helm history horizon -n openstack -o json > "$WORK/history.json"
python3 - "$CHART" "$WORK" <<'PY'
import json, sys
from pathlib import Path
import yaml
chart, work = map(Path, sys.argv[1:])
meta = yaml.safe_load((chart / 'Chart.yaml').read_text())
history = json.loads((work / 'history.json').read_text())
latest = max(history, key=lambda x: int(x['revision']))
assert latest['status'] == 'deployed', 'Release chua deployed; dung lai'
assert latest['chart'] == 'horizon-' + str(meta['version']), 'Chart local khac release; dung lai'
(work / 'rollback-revision.txt').write_text(str(latest['revision']) + '\n')
PY
cat > "$WORK/2025.2-values.yaml" <<'EOF'
images:
  tags:
    horizon: quay.io/airshipit/horizon@sha256:6c11946d6ac14d0cd0404a1e66c6a194b30a13d46387c0388f772dc759dd8567
conf:
  horizon:
    extra_panels: []
EOF
helm template horizon "$CHART" -n openstack --is-upgrade \
  -f "$WORK/before.yaml" -f "$WORK/2025.2-values.yaml" \
  > "$WORK/rendered.yaml"
printf 'Configuration saved: %s\n' "$WORK"
helm upgrade horizon "$CHART" -n openstack \
  -f "$WORK/before.yaml" -f "$WORK/2025.2-values.yaml" \
  --no-hooks --wait --timeout 10m
kubectl -n openstack rollout status deployment/horizon --timeout=180s
kubectl -n openstack rollout status deployment/horizon --timeout=300s
kubectl -n openstack exec deployment/horizon -c horizon -- \
  python3 -c 'from importlib.metadata import version; print("Horizon:", version("horizon"))'
)
```

`--no-hooks` bỏ qua DB init/sync hooks trong lần đổi giao diện này; không phải cờ dùng cho cài mới. Helm vẫn có thể render hook Jobs vào file để xem, nhưng không chạy chúng. Snapshot/render chứa credentials, không commit lên Git.

Sau khi rollout: mở lại HTTPS Horizon, đăng xuất/đăng nhập nếu session cũ lỗi, kiểm tra Instances, Networks và Volumes. Nếu DB/schema hoặc cấu hình không tương thích, quay lại release trước thay vì chạy migrations để thử sửa. Octavia Dashboard vẫn chưa có sau thao tác này.

## 8. Quay lại khi dashboard mới lỗi

Lấy đúng đường dẫn `Configuration saved` đã in ở bước 7. Không đoán revision 3 vì release có thể đã được upgrade nhiều lần.

```bash
# Thay đường dẫn dưới bằng thư mục switch-* đã in ở bước 7.
WORK="$HOME/osh-lab/horizon-version/switch-YYYYMMDD-HHMMSS"
REVISION=$(cat "$WORK/rollback-revision.txt")
helm rollback horizon "$REVISION" -n openstack \
  --no-hooks --wait --timeout 10m
kubectl -n openstack rollout status deployment/horizon --timeout=180s
```

Rollback này khôi phục cấu hình Helm/image trước đó. Vì lần chuyển trên không chạy DB hooks, nó không chủ động migrate database. Vẫn cần kiểm tra dashboard sau rollback. Upgrade và rollout đã được xác nhận thành công ở mục 10; đăng nhập và các trang dashboard chưa được nghiệm thu.

## 9. Revision mới nhưng exec còn trả về phiên bản cũ

Lần chuyển ghi nhận revision 4 deployed, snapshot `/home/bastion/osh-lab/horizon-version/switch-20261009-070239`, nhưng lệnh exec ngay sau upgrade trả về Horizon 25.7.4.dev29. ```bash
kubectl -n openstack get deployment horizon \
  -o jsonpath='{range .spec.template.spec.containers[*]}{.name}{" image="}{.image}{"\n"}{end}'

  -o custom-columns='NAME:.metadata.name,READY:.status.containerStatuses[*].ready,IMAGE:.spec.containers[*].image,IMAGE_ID:.status.containerStatuses[*].imageID'

Nếu selector không trả về pod, dùng `kubectl -n openstack get pods -l application=horizon -o wide` và đối chiếu pod web với DB Jobs. Nếu rollout timeout, giữ nguyên release và đọc trạng thái/events pod mới trước khi upgrade lại. Nếu rollout thành công, kiểm tra lại phiên bản; cần chọn đúng pod mới khi pod cũ còn terminating. Đường dẫn snapshot trên chỉ là kết quả của cụm hiện tại, không hardcode vào quy trình dựng mới.

## 11. Kiểm tra Gateway sau khi đổi image

Trình duyệt báo `upstream connect error or disconnect/reset before headers; remote connection failure`. Chuyển package/rollout đã thành công nhưng dashboard qua Gateway chưa hoạt động. Log Horizon đã chạy Apache, collectstatic/compress thành công và trả 302 cho kube-probe; không có bằng chứng startup hỏng trong log đã cung cấp. DeprecationWarning và cảnh báo Apache ServerName không đủ để kết luận nguyên nhân. Cần kiểm tra endpoint mới, backend port và kết nối từ Envoy trước khi đổi values hoặc rollback.

```bash
kubectl -n openstack get svc horizon-int -o yaml
kubectl -n openstack get endpointslices \
  -l kubernetes.io/service-name=horizon-int -o yaml
kubectl -n openstack get httproute -l lab-component=openstack-gateway
kubectl -n envoyproxy-gateway-system get pods -o wide

kubectl -n openstack exec -i deployment/horizon -c horizon -- python3 - <<'PY'
import urllib.request
for url in ['http://127.0.0.1:80/', 'http://horizon-int.openstack.svc.cluster.local:80/']:
    request = urllib.request.Request(url, headers={'Host': 'horizon.lab.test'})
    try:
        with urllib.request.urlopen(request, timeout=8) as response:
            print(url, 'HTTP', response.status)
    except Exception as error:
        print(url, type(error).__name__, str(error))
PY
```

Probe Python có thể theo redirect sang trang đăng nhập; HTTP 400/403 vẫn chứng minh có HTTP server trả lời nhưng chưa chứng minh dashboard hoạt động. Probe trong pod Horizon không thay thế kiểm tra đường truyền từ pod Envoy. Chưa thực hiện sửa port, restart Envoy hoặc migration vì chưa có bằng chứng tương ứng.

### 11.1. Phân biệt lỗi Horizon với pod sandbox bị tạo lại

Describe pod sau chuyển image xác nhận: Horizon restart 6 lần, init container cũng restart 6 lần; events có SandboxChanged, PodNetworkRemoved/Configured lặp lại, PodReadyToStartContainers=False. Container thoát 137 với reason Error, không phải OOMKilled trong output đã gửi. Có readiness/liveness timeout khi theo redirect sang /auth/login/. Liveness initialDelay=180s nhưng lần container gần nhất chỉ sống khoảng 74s, vì vậy không quy mọi restart cho liveness hoặc phiên bản Horizon.

Cần kiểm tra node/container runtime/CNI song song với HTTP login. Đây là bằng chứng pod sandbox bị tạo lại; chưa xác định tác nhân. Không kết luận Kube-OVN, thiếu RAM hoặc downgrade là nguyên nhân khi chưa có log tương ứng.

```bash
kubectl -n openstack get pods -o wide
kubectl get events -A --sort-by=.metadata.creationTimestamp | tail -n 60
kubectl describe node controlplane-01

talosctl -n 192.168.207.137 services
talosctl -n 192.168.207.137 logs kubelet --tail 150
talosctl -n 192.168.207.137 logs containerd --tail 100
```

Địa chỉ/node ở đây thuộc cụm lab hiện tại. Khi dựng cụm khác dùng node nơi pod Horizon được schedule. Log có thể chứa thông tin nội bộ, không gửi credentials. Nếu node/API log không ổn định, không tăng probe timeout hoặc đổi Gateway để che mất lỗi sandbox.

### 11.2. Lỗi rộng hơn Horizon đã được xác nhận

Log tiếp theo có kube-scheduler và kube-controller-manager CrashLoopBackOff, Kube-OVN CNI healthcheck timeout, Keystone không Ready và Nova healthcheck timeout. Kubelet cập nhật lease qua localhost:7445 cũng timeout. Vì vậy không thể coi đây là lỗi riêng image Horizon. Node báo memory requests 82%, limits 252%; nhiều dịch vụ OpenStack không khai báo requests/limits. Những tỷ lệ này là khai báo scheduling, không phải phép đo RAM thực tế và chưa chứng minh OOM.

Lệnh `talosctl logs containerd` vừa dùng trả log socket `/system/run/containerd/containerd.sock` với namespace system (apid/trustd). Cần xem service `cri` để kiểm tra runtime phục vụ Kubernetes; giữ phân biệt này khi đọc log.

```bash
talosctl -n 192.168.207.137 logs cri --tail 120
talosctl -n 192.168.207.137 dmesg | grep -Ei 'oom|out of memory|killed process|I/O error|hung task|blocked for' || true
kubectl get node controlplane-01 \
  -o jsonpath='{range .status.conditions[*]}{.type}{"="}{.status}{" reason="}{.reason}{"\n"}{end}'
```

Kiểm tra CPU/RAM, CPU ready và datastore latency của VM controlplane trên hypervisor trong lúc xảy ra lỗi. Nếu log kernel xác nhận OOM thì xử lý RAM; nếu nhiều dịch vụ bị treo do CPU/storage thì xử lý tài nguyên tương ứng. Không kết luận từ limits tổng cộng và không restart cri tùy tiện: thao tác đó có thể gián đoạn toàn bộ pod trên node.
