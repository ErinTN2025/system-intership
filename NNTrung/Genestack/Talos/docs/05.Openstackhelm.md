# OpenStack Helm trên Talos — triển khai và vận hành lab

## 1. Phạm vi và cách đọc

Tài liệu này mô tả cấu hình nền của lab, theo thứ tự triển khai mới: Talos/storage → Helm → RabbitMQ, MariaDB, Memcached → Keystone, Placement, Glance → OVN dùng chung → libvirt → Neutron → Nova → Rook/Cinder → Horizon → kiểm thử.

**Cụm hiện tại đã chuyển một số dịch vụ sang RabbitMQ Operator theo [file 06](06.OpenstackOperatorMigration.md). Không chạy lại các lệnh cài nền dưới đây lên cụm hiện tại:** values cũ có thể đưa endpoint về RabbitMQ cũ. Khi chỉnh cấu hình cụm đang chạy, dùng mục 13 để lấy values hiện tại làm nền. MariaDB vẫn giữ OpenStack Helm; không triển khai MariaDB Operator trong quy trình này.

Mỗi bước gồm: lưu cấu hình → render → kiểm tra manifest → cài → kiểm tra dịch vụ. `helm template` chỉ sinh YAML, `helm upgrade --install` mới thay đổi cluster. Render thành công chưa chứng minh runtime hoạt động. Chạy từng khối, chỉ sang bước tiếp theo khi bước trước đạt; đây không phải script chạy một lần không cần quan sát.

| Thành phần | Vị trí và vai trò |
|---|---|
| Bastion | `192.168.207.138`, chạy Bash/kubectl/Helm/talosctl và CLI |
| Control plane | `controlplane-01`, `192.168.207.137` |
| Compute | `workerplane-01`, `192.168.207.139`; không dùng worker-02 |
| Local-path control plane | `/var/mnt/local-storage` trên user volume Talos |
| Local-path worker | `/var/mnt/local-path-provisioner` trên `/dev/sdb1` |
| Ceph OSD | Disk `/dev/sdc` riêng trên worker |
| Mạng VM | Neutron dùng OVN NB/SB của Kube-OVN; Nova dùng socket OVS của node |

Sau thay disk, volume local-path worker khoảng **9 GB**, không còn 60 GB như lần đầu. PVC local-path không tạo thêm dung lượng và không phải quota disk. Nova instance disk không tự chuyển sang sdb chỉ vì cài local-path. Ceph một OSD/một bản sao phục vụ lab, không cung cấp HA.

```bash
  neutron) version='2026.1.69+4e05862fc';;
```

## 3. Local-path provisioner

Cho phép helper pod trước khi cấp PVC. Hai đường dẫn dưới đây phải là volume Talos đã mount, không chỉ là thư mục trên disk hệ điều hành.

```bash
kubectl create namespace local-path-storage --dry-run=client -o yaml | kubectl apply -f -
kubectl label namespace local-path-storage pod-security.kubernetes.io/enforce=privileged --overwrite
kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.37/deploy/local-path-storage.yaml
kubectl -n local-path-storage patch configmap local-path-config --type=merge \
  -p '{"data":{"config.json":"{\"nodePathMap\":[{\"node\":\"controlplane-01\",\"paths\":[\"/var/mnt/local-storage\"]},{\"node\":\"workerplane-01\",\"paths\":[\"/var/mnt/local-path-provisioner\"]},{\"node\":\"DEFAULT_PATH_FOR_NON_LISTED_NODES\",\"paths\":[]}]}"}}'
kubectl -n local-path-storage rollout status deployment/local-path-provisioner --timeout=180s
kubectl -n local-path-storage get configmap local-path-config -o jsonpath='{.data.config\.json}{"\n"}'
kubectl get storageclass local-path -o yaml
```

`WaitForFirstConsumer`: PVC có thể Pending trước khi pod sử dụng được schedule. PV local gắn với node; chuyển pod không tự chuyển dữ liệu. Sau bước 4, kiểm tra PVC Bound và đường dẫn PV để xác nhận storage.

```bash

  > /tmp/kube-ovn-defaults.yaml

python3 - <<'PY'
from pathlib import Path
import yaml

v = yaml.safe_load(Path("/tmp/kube-ovn-defaults.yaml").read_text())
paths = []

def scan(obj, path=()):
    if isinstance(obj, dict):
        for k, value in obj.items():
            if k == "ENABLE_EXTERNAL_VPC":
                paths.append(path + (k,))
            scan(value, path + (k,))

scan(v)
assert len(paths) == 1, f"Đường dẫn không duy nhất: {paths}"
override = True
for key in reversed(paths[0]):
    override = {key: override}

p = Path.home() / "osh-lab/overrides/kube-ovn/shared-ovn.yaml"
p.write_text(yaml.safe_dump(override, sort_keys=False))
print(p.read_text())
PY
```

### Libvirt: giữ bản chart Talos đã hoạt động

**Điều kiện:** có `~/osh-lab/charts/libvirt` version `2026.1.29+a34a2f9b9`, đã sửa cho Talos. Chart gốc tải từ repo không tương đương bản này. Bản ghi cũ chưa có toàn bộ patch cuối cùng; vì vậy cần giữ chart trên bastion bằng snapshot mục 2. Nếu mất bản chart đó, phải hoàn thiện patch/kiểm thử lại trước khi triển khai tiếp, không coi values dưới đây là đủ để dựng lại libvirt từ chart gốc.

```bash
  backend: [openvswitch]

  dynamic:
    targeted:
      openvswitch:
        libvirt:
          pod: []
```

## 8. Nova: socket libvirt và OVS

Nova dùng backend `openvswitch` cho os-vif để cắm port, dù Neutron dùng OVN. Compute cần cả `/run/libvirt` và `/run/openvswitch`.

Patch template kiểm tra cấu trúc gốc trước khi sửa; chạy lại giữ phần đã patch. Nếu đổi chart version, không bỏ assertion để sửa mù.

```bash
python3 - <<'PY'
from pathlib import Path
p = Path.home() / 'osh-lab/charts/nova/templates/daemonset-compute.yaml'
s = p.read_text()
pairs = [
('            - name: run\n              mountPath: /run\n',
 '            - name: run\n              mountPath: /run/libvirt\n'),
('        - name: run\n          hostPath:\n            path: /run\n',
 '        - name: run\n          hostPath:\n            path: /run/libvirt\n            type: DirectoryOrCreate\n')]
for old, new in pairs:
    if old in s:
        assert s.count(old) == 1, 'Template khac du kien'
        s = s.replace(old, new)
    else:
        assert new in s, 'Khong tim thay cau truc goc/da patch'
p.write_text(s)
PY
```

Gộp defaults và distro values trước khi thêm socket, để giữ đầy đủ list mounts/volumes. Tạo một override cuối cùng thay vì nhiều file sửa sau đè file trước.

```bash
python3 - <<'PY'
from copy import deepcopy
from pathlib import Path
import yaml
root = Path.home() / 'osh-lab'
def merge(a, b):
    result = deepcopy(a)
    for k, v in b.items():
        result[k] = merge(result[k], v) if isinstance(v, dict) and isinstance(result.get(k), dict) else deepcopy(v)
    return result
base = yaml.safe_load((root / 'charts/nova/values.yaml').read_text())
distro = yaml.safe_load((root / 'overrides/nova/2026.1-ubuntu_noble.yaml').read_text()) or {}
values = merge(base, distro)
mounts = deepcopy(values['pod']['mounts']['nova_compute']['nova_compute'])
for field, item in [
    ('volumeMounts', {'name': 'shared-ovn-run', 'mountPath': '/run/openvswitch'}),
    ('volumes', {'name': 'shared-ovn-run', 'hostPath': {'path': '/run/openvswitch', 'type': 'Directory'}})]:
    items = mounts.setdefault(field, [])
    assert not any(x.get('name') == item['name'] for x in items), 'Socket da co; kiem tra values'
    items.append(item)
override = {
    'conf': {'ceph': {'enabled': False}, 'enable_iscsi': False,
             'nova': {'os_vif_ovs': {'ovsdb_interface': 'vsctl', 'ovsdb_connection': 'unix:/run/openvswitch/db.sock'}}},
    'network': {'backend': ['openvswitch']},
    'dependencies': {'dynamic': {'targeted': {'openvswitch': {'compute': {'pod': []}}}}},
    'bootstrap': {'wait_for_computes': {'enabled': False}},
    'pod': {'mounts': {'nova_compute': {'nova_compute': mounts}}}}
(root / 'overrides/nova/talos-lab.yaml').write_text(yaml.safe_dump(override, sort_keys=False))
```

Trước khi attach RBD volume, nạp Ceph secret vào libvirt. Giải đúng lớp base64 của Kubernetes rồi truyền chuỗi Ceph key cho `virsh --file`, không dùng `--plain`.

```bash
LIBVIRT_POD=$(kubectl -n openstack get pod -l application=libvirt -o jsonpath='{.items[0].metadata.name}')

kubectl -n openstack exec -i "$LIBVIRT_POD" -c libvirt -- \
  sh -c '
    set -e
    umask 077
    trap "rm -f /tmp/cinder-secret.xml" EXIT
    cat > /tmp/cinder-secret.xml
    virsh secret-define /tmp/cinder-secret.xml
  ' <<'EOF'
<secret ephemeral='no' private='yes'>
  <uuid>457eb676-33da-42ec-9a8c-9293d545c337</uuid>
  <usage type='ceph'>
    <name>client.cinder secret</name>
  </usage>
</secret>
EOF
```

Nạp key đúng dạng, **không dùng `--plain`**:

```bash
set -o pipefail

kubectl -n openstack get secret cinder-rook-client-key \
  -o jsonpath='{.data.key}' |
  base64 -d |
  kubectl -n openstack exec -i "$LIBVIRT_POD" -c libvirt -- \
    sh -c '
      set -e
      umask 077
      trap "rm -f /tmp/cinder-client-key" EXIT
      cat > /tmp/cinder-client-key
      test -s /tmp/cinder-client-key
      virsh secret-set-value \
        457eb676-33da-42ec-9a8c-9293d545c337 \
        --file /tmp/cinder-client-key
    '
```


Cách nạp secret này còn thủ công: sau khi libvirt pod được tạo lại, kiểm tra `virsh secret-list` và nạp lại nếu secret/key mất. Chưa có cơ chế tự nạp sau restart; không coi cấu hình này đã hoàn chỉnh về persistence.

## 13. Cập nhật Helm và restart pod

### 13.1. Sửa gì, lưu ở đâu?

| Muốn đổi | Nơi xử lý |
|---|---|
| Image, replicas, resources, endpoint, cấu hình ứng dụng | Override YAML; tra key qua `helm show values` |
| hostPath/startup không có values hỗ trợ | Chart local `~/osh-lab/charts/<service>/templates` |
| CNI/OVN | Release `kube-ovn`, namespace `kube-system` |
| Pool/client Ceph | Manifest trong `~/osh-lab/overrides/rook`, do Rook reconcile |
| Restart cùng cấu hình | `kubectl rollout restart` |
| Đổi chart version | Kiểm tra chart mới và tính tương thích patch Talos trước |

Sửa file trên bastion chưa đổi pod. Render để xem trước, upgrade để áp dụng. Workload rollout khi pod template thay đổi; không phải mọi ConfigMap/Secret thay đổi đều tự restart.

### 13.2. Ví dụ sửa Nova trên cụm hiện tại

Lấy effective values hiện tại làm nền để giữ endpoint RabbitMQ đã chuyển ở file 06. Đây là cập nhật **cùng chart version**. Không tự mang toàn bộ defaults cũ sang chart version mới.

```bash
umask 077
update_dir="$HOME/osh-lab/snapshots/nova-update-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$update_dir"
helm -n openstack history nova
helm get values nova -n openstack --all -o yaml > "$update_dir/before.yaml"
printf '{}\n' > "$update_dir/change.yaml"
nano "$update_dir/change.yaml"
helm template nova ~/osh-lab/charts/nova -n openstack --is-upgrade \
  -f "$update_dir/before.yaml" -f "$update_dir/change.yaml" > "$update_dir/rendered.yaml"
```

Thêm đúng key cần đổi vào `change.yaml`. Đọc phần thay đổi trong rendered; xác nhận RabbitMQ vẫn `rabbitmq-genestack`, socket libvirt/OVS còn đủ. Manifest chứa Secret, không gửi raw. Khi đúng mới chạy:

```bash
helm upgrade nova ~/osh-lab/charts/nova -n openstack \
  -f "$update_dir/before.yaml" -f "$update_dir/change.yaml" --wait --timeout 15m
helm -n openstack status nova
kubectl -n openstack get pods -l application=nova -o wide
kubectl -n openstack rollout status daemonset/nova-compute-default --timeout=180s
```

Ghi lại đường dẫn `update_dir`, nội dung thay đổi và kết quả. Terminal mới phải đặt lại biến theo thư mục đã tạo. Với Keystone/Glance/Horizon dùng chart repo và `--version` đúng release hiện tại; libvirt/Neutron/Cinder dùng chart local. Không dùng snapshot của dịch vụ khác làm nền.

Không dùng `kubectl edit` làm cấu hình chính: Helm có thể ghi đè lần sau. Không dùng `--force`, uninstall/reinstall hoặc xóa PVC làm thao tác cập nhật mặc định. Helm rollback không khôi phục database/PVC.

## 15. Hồ sơ bàn giao và giới hạn

Giữ chart đã patch, overrides, helper và snapshots; ghi chart version, thứ tự values, release/namespace, thay đổi và kết quả kiểm thử. Không dùng rendered YAML để `kubectl apply` thay Helm quản lý release.

Tài liệu được cơ cấu từ cấu hình/kết quả lab, **chưa kiểm thử lại toàn bộ trên cụm trống**. Điểm chưa đủ để dựng lại từ chart gốc là bản patch libvirt; phải giữ chart hoạt động. Metadata, provider network và cơ chế tự nạp Ceph secret sau restart còn là các hạng mục riêng.

File 06 ghi RabbitMQ Operator và kiểm thử sau chuyển đổi. Gateway API, Octavia, Barbican có thể bổ sung sau, không yêu cầu cài lại dịch vụ đang chạy tốt.

Tham khảo: [Helm values](https://helm.sh/docs/chart_template_guide/values_files/), [Helm upgrade](https://helm.sh/docs/helm/helm_upgrade/), [virsh](https://libvirt.org/manpages/virsh.html).
