# Chuyển RabbitMQ sang Operator cho OpenStack trên Talos

Tài liệu bàn giao kỹ thuật — cập nhật ngày 07/10/2026. Tiếp nối [05.Openstackhelm.md](05.Openstackhelm.md).

## 1. Mục đích và phạm vi

Chuyển RabbitMQ từ chart server OpenStack-Helm sang mô hình Operator của Genestack. Giữ nguyên MariaDB hiện tại theo phạm vi đã chốt. Các dịch vụ OpenStack tiếp tục được quản lý bằng Helm; giữ các chart local đã sửa cho Talos và shared OVN.

Phạm vi gồm RabbitMQ Cluster Operator, Messaging Topology Operator, cert-manager phục vụ webhook, cấu hình messaging của các dịch vụ và kiểm tra sau chuyển đổi. MariaDB Operator không thuộc đợt triển khai này. Kube-OVN, Rook-Ceph, libvirt, Memcached, Gateway API, Octavia và Barbican được xử lý trong các tài liệu riêng.

Không thay MariaDB hoặc khởi tạo lại database trong quy trình hiện tại. Các dịch vụ đã cài ổn được giữ nguyên, chỉ điều chỉnh phần RabbitMQ cần thiết.

### 1.1. Mô hình quản lý

| Thành phần | Mô hình ở file 05 | Mô hình đích |
| --- | --- | --- |
| RabbitMQ server | Chart OpenStack-Helm tạo StatefulSet | Cluster Operator quản lý `RabbitmqCluster` |
| RabbitMQ user/vhost/quyền | Job `rabbit-init` của chart dịch vụ | Topology Operator quản lý `User`, `Vhost`, `Permission` |
| MariaDB server | Chart OpenStack-Helm | Giữ nguyên |
| Database/user/grant | Cơ chế khởi tạo của OpenStack-Helm | Giữ nguyên |
| Nova/Neutron/Cinder/Glance/Keystone | Helm | Giữ Helm, điều chỉnh backend endpoints và provisioning |

Operator là controller quản lý vòng đời tài nguyên. Controller có thể được cài bằng Helm; khác biệt nằm ở cách quản lý server và tài nguyên ứng dụng qua CR, không nằm ở việc có dùng lệnh Helm hay không.

## 5. Tạo broker và topology OpenStack

### 5.1. RabbitmqCluster cho lab

Tên `rabbitmq-genestack` tránh xung đột Service `rabbitmq` cũ. Một replica, PVC 1 GiB local-path, RAM 1 GiB và node affinity control plane là cấu hình lab; không tương đương HA ba replicas của baseline Genestack. Image `4.3.5-management` giữ cùng phiên bản server với lab cũ. `disk_free_limit.absolute=200MB` là ngưỡng disk alarm, không phải quota PVC.

```bash
cat > ~/osh-lab/operators/rabbitmq-genestack.yaml <<'EOF'
apiVersion: rabbitmq.com/v1beta1
kind: RabbitmqCluster
metadata:
  name: rabbitmq-genestack
  namespace: openstack
spec:
  replicas: 1
  image: rabbitmq:4.3.5-management
  service:
    type: ClusterIP
  persistence:
    storageClassName: local-path
    storage: 1Gi
  resources:
    requests:
      cpu: 250m
      memory: 1Gi
    limits:
      memory: 1Gi
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: kubernetes.io/hostname
                operator: In
                values:
                  - controlplane-01
  tolerations:
    - key: node-role.kubernetes.io/control-plane
      operator: Exists
      effect: NoSchedule
  rabbitmq:
    additionalConfig: |
      disk_free_limit.absolute = 200MB
EOF

kubectl apply -f ~/osh-lab/operators/rabbitmq-genestack.yaml

  -l app.kubernetes.io/name=rabbitmq-genestack

### 5.2. Credentials adapter và topology

Các Secret `<service>-rabbitmq-user` cũ chỉ có key `RABBITMQ_CONNECTION`. Script đọc connection URI tại bastion, tạo Secret adapter có username/password cho Operator và ba CR cho mỗi dịch vụ. Giữ credentials cũ để ứng dụng không cần đổi mật khẩu. Script này đã chạy thành công cho Nova, Neutron, Cinder, Glance, Keystone.

Mỗi vhost mặc định quorum; user service không có administrator tags. Queues RPC/notifications do clients khai báo sau khi kết nối. Đây là lựa chọn của lab, không sao chép các queues runtime hoặc toàn bộ Queue CR mẫu của Genestack.

```bash
python3 - <<'PY'
import base64
import json
import subprocess
from urllib.parse import urlsplit, unquote

namespace = 'openstack'
cluster = 'rabbitmq-genestack'
services = ['nova', 'neutron', 'cinder', 'glance', 'keystone']
objects = []

def resource(kind, name, spec):
    return {'apiVersion': 'rabbitmq.com/v1beta1', 'kind': kind,
            'metadata': {'name': name, 'namespace': namespace,
                         'labels': {'lab-role': 'rabbitmq-genestack-topology'}},
            'spec': spec}

for service in services:
    try:
        result = subprocess.run(
            ['kubectl', '-n', namespace, 'get', 'secret',
             service + '-rabbitmq-user', '-o', 'json'],
            check=True, capture_output=True, text=True)
        secret = json.loads(result.stdout)
        connection = base64.b64decode(
            secret['data']['RABBITMQ_CONNECTION'], validate=True).decode().strip()
        uri = urlsplit(connection)
        username = unquote(uri.username or '')
        password = unquote(uri.password or '')
        vhost = unquote(uri.path[1:]) if uri.path.startswith('/') else ''
        if uri.scheme not in ('rabbit', 'amqp', 'amqps'):
            raise ValueError()
        if username != service or vhost != service or not password:
            raise ValueError()
        if not uri.hostname or ',' in uri.netloc:
            raise ValueError()
    except Exception:
        raise SystemExit('Dung: khong doc/parse duoc Secret cua ' + service
                         + '; KHONG gui connection string/password len chat.')
    name = 'gs-' + service
    objects.append({'apiVersion': 'v1', 'kind': 'Secret',
                    'metadata': {'name': name + '-rabbitmq-credentials',
                                 'namespace': namespace,
                                 'labels': {'rabbitmq.com/topology-operator': 'true'}},
                    'type': 'Opaque',
                    'data': {key: base64.b64encode(value.encode()).decode()
                             for key, value in [('username', username),
                                                ('password', password)]}})
    ref = {'name': cluster, 'namespace': namespace}
    objects.append(resource('Vhost', name + '-vhost',
                            {'name': vhost, 'defaultQueueType': 'quorum',
                             'rabbitmqClusterReference': ref}))
    objects.append(resource('User', name + '-user',
                            {'tags': [], 'importCredentialsSecret':
                             {'name': name + '-rabbitmq-credentials'},
                             'rabbitmqClusterReference': ref}))
    objects.append(resource('Permission', name + '-permission',
                            {'vhost': vhost,
                             'userReference': {'name': name + '-user'},
                             'permissions': {'configure': '.*', 'write': '.*', 'read': '.*'},
                             'rabbitmqClusterReference': ref}))
    print('Da kiem tra credentials/vhost: ' + service + ' (khong hien password)')

result = subprocess.run(['kubectl', 'apply', '-f', '-'],
                        input=json.dumps({'apiVersion': 'v1', 'kind': 'List',
                                          'items': objects}),
                        capture_output=True, text=True)
if result.returncode:
    raise SystemExit('Apply loi, co the da tao mot phan. Kiem tra resources/events; '
                     'khong in stderr/payload Secret. Khong doi endpoint.')
print('Da apply 5 Secrets va 15 topology resources. Can cho reconcile.')
PY
```

```bash
for kind in users.rabbitmq.com vhosts.rabbitmq.com permissions.rabbitmq.com; do
  kubectl -n openstack wait "$kind" \
    -l lab-role=rabbitmq-genestack-topology \

done
kubectl -n openstack exec rabbitmq-genestack-server-0 -c rabbitmq -- rabbitmqctl list_vhosts
kubectl -n openstack exec rabbitmq-genestack-server-0 -c rabbitmq -- rabbitmqctl list_users

Giữ `secret_rabbitmq=true` trong current values để chart cập nhật Secret connection. Các cờ quorum/durable đã bật trong năm release và được giữ nguyên.

Quy trình mỗi release: lưu current values → render bằng đúng chart → kiểm tra hostname/user/vhost/credentials và jobs → upgrade → kiểm tra rollout/connections/consumers. `helm template` chỉ render, không xác nhận kết nối runtime. Không cần thêm lại override distro khi đã dùng đầy đủ effective values của đúng release.

### 6.3. Chuyển Nova và kiểm tra cell mappings

Script chuẩn bị đã PASS trên chart local. Giữ current values của đúng lần cutover; không chạy lại để xuất baseline từ release failed. File nova-current.yaml trên cụm bàn giao đã được xuất lại sau migration, không còn được coi là baseline revision 3.

```bash
python3 - <<'PY'
import base64
import json
import os
from pathlib import Path
import subprocess
from urllib.parse import urlsplit, unquote
import yaml

os.umask(0o077)
service = 'nova'
root = Path.home() / 'osh-lab/operators/rabbitmq-cutover'
chart = Path.home() / 'osh-lab/charts/nova'
meta = yaml.safe_load((chart / 'Chart.yaml').read_text())
assert str(meta['version']) == '2026.1.44+89c5a3c84', 'Chart local khac version release; dung lai'

def run(args):
    result = subprocess.run(args, capture_output=True, text=True)
    if result.returncode:
        raise SystemExit('Lenh that bai: ' + args[0] + ' ' + args[1]
                         + '; chua upgrade. Kiem tra loi rieng, khong gui credentials.')
    return result.stdout

current = root / 'nova-current.yaml'
if current.exists():
    print('Giu file current da ton tai; khong ghi de baseline')
else:
    current.write_text(run(['helm', 'get', 'values', service, '-n', 'openstack', '--all', '-o', 'yaml']))
rendered = root / 'nova-rendered.yaml'
rendered.write_text(run(['helm', 'template', service, str(chart), '-n', 'openstack',
                        '--is-upgrade', '-f', str(current), '-f', str(root / 'endpoint.yaml')]))
docs = [d for d in yaml.safe_load_all(rendered.read_text()) if isinstance(d, dict)]
secret = next(d for d in docs if d.get('kind') == 'Secret'
              and d.get('metadata', {}).get('name') == service + '-rabbitmq-user')
uri = urlsplit(base64.b64decode(secret['data']['RABBITMQ_CONNECTION']).decode().strip())
adapter = json.loads(run(['kubectl', '-n', 'openstack', 'get', 'secret',
                         'gs-nova-rabbitmq-credentials', '-o', 'json']))
password = base64.b64decode(adapter['data']['password']).decode()
assert uri.hostname == 'rabbitmq-genestack.openstack.svc.cluster.local', 'Sai host'
assert unquote(uri.username or '') == service, 'Sai user'
assert unquote(uri.path) == '/' + service, 'Sai vhost'
assert unquote(uri.password or '') == password, 'Password khong khop broker moi'
jobs = [d.get('metadata', {}).get('name', '') for d in docs if d.get('kind') == 'Job']
assert not any('rabbit' in name.lower() for name in jobs), 'Con RabbitMQ init job'
print('Chart local: ' + str(meta['version']))
print('Jobs trong render: ' + ', '.join(jobs))
print('PASS Nova: endpoint/credentials dung; khong con RabbitMQ init job; chua upgrade.')
PY
```

Nova cell mappings lưu transport URL trong database. Cell0 dùng `none:///`; cell1 phải trỏ đúng broker mới. Truy vấn SQL chỉ đọc dưới đây đã được kiểm chứng trên lab và tránh thời gian khởi tạo nova-manage:

```bash
NOVA_API_CONTAINER=$(kubectl -n openstack get deployment nova-api-osapi \
  -o jsonpath='{.spec.template.spec.containers[0].name}')

kubectl -n openstack exec -i deployment/nova-api-osapi \
  -c "$NOVA_API_CONTAINER" -- python3 - <<'PY'
import configparser
from pathlib import Path
from urllib.parse import urlsplit, unquote
import pymysql

config = configparser.ConfigParser(interpolation=None, strict=False)
config.read('/etc/nova/nova.conf')
for path in sorted(Path('/etc/nova/nova.conf.d').glob('*.conf')):
    config.read(str(path))
uri = urlsplit(config.get('api_database', 'connection', fallback=''))
if not uri.hostname or not uri.username or not uri.path.strip('/'):
    raise SystemExit('API DB config thieu thong tin; khong in credentials')
try:
    db = pymysql.connect(host=uri.hostname, port=uri.port or 3306,
                         user=unquote(uri.username), password=unquote(uri.password or ''),
                         database=unquote(uri.path.lstrip('/')), connect_timeout=5,
                         read_timeout=8, write_timeout=8)
    try:
        with db.cursor() as cursor:
            cursor.execute('SELECT 1')
            assert cursor.fetchone()[0] == 1
            print('SQL SELECT 1: PASS')
            cursor.execute('SELECT name, uuid, transport_url FROM cell_mappings')
            for name, uuid, transport in cursor.fetchall():
                host = 'none (cell0)' if (transport or '').startswith('none:') else urlsplit(transport or '').hostname
                print('cell=' + str(name) + ', uuid=' + str(uuid) + ', transport_host=' + str(host))
    finally:
        db.close()
except Exception as exc:
    code = exc.args[0] if exc.args and isinstance(exc.args[0], int) else 'n/a'
    raise SystemExit('SQL_CHECK_FAILED: ' + type(exc).__name__ + ', code=' + str(code))
PY

```

Điều kiện đạt: cell0 dùng transport none, cell1 trỏ rabbitmq-genestack.openstack.svc.cluster.local. Cụm bàn giao đã xác nhận cell1 UUID cba78f32-c45c-45c1-b34b-d0a21c9fa794 giữ nguyên và host đúng bằng truy vấn SQL. Không xóa/tạo lại cell để đổi broker.

### 6.4. Cấu hình client và kiểm tra API

Virtualenv cung cấp OpenStack CLI; cần nạp credentials và đường truy cập API trong shell hiện tại. Cấu hình dưới dùng cách port-forward và biến OS_* của file 05, không thay catalog hoặc dịch vụ trong cluster.

Mở ba terminal trên cùng bastion và giữ các port-forward chạy. Nếu port đã được bind bởi phiên port-forward đang hoạt động thì dùng phiên đó, không mở trùng:

```bash
# Terminal 1
kubectl -n openstack port-forward svc/keystone-api 5000:5000
```

```bash
# Terminal 2
kubectl -n openstack port-forward svc/nova-api 8774:8774
```

```bash
# Terminal 3
kubectl -n openstack port-forward svc/neutron-server 9696:9696
```

Ở terminal kiểm tra riêng, nạp credentials admin hiện có từ Secret nova-keystone-admin mà không in password. Các biến username/project/domain lấy từ chính Secret thay vì giả định giá trị:

```bash
source ~/openstack-client/bin/activate

# Chạy trong shell hiện tại để giữ các biến cho những lệnh CLI sau.
load_osh_admin() {
  local auth_key auth_value
  for auth_key in OS_USERNAME OS_PASSWORD OS_PROJECT_NAME OS_USER_DOMAIN_NAME OS_PROJECT_DOMAIN_NAME; do
    auth_value=$(kubectl -n openstack get secret nova-keystone-admin \
      -o "jsonpath={.data.${auth_key}}" | base64 -d) || return 1
    if [ -z "$auth_value" ]; then
      printf 'Thieu key %s trong Secret; dung nap credentials.\n' "$auth_key"
      return 1
    fi
    export "$auth_key=$auth_value"
  done
  export OS_AUTH_TYPE=password
  export OS_IDENTITY_API_VERSION=3
  export OS_AUTH_URL=http://127.0.0.1:5000/v3
  export OS_COMPUTE_ENDPOINT_OVERRIDE=http://127.0.0.1:8774/v2.1
  export OS_NETWORK_ENDPOINT_OVERRIDE=http://127.0.0.1:9696
}

if load_osh_admin; then
  timeout 20s openstack token issue -f value -c expires
  echo "token check exit code: $?"
  timeout 20s openstack compute service list
  echo "compute check exit code: $?"
  timeout 20s openstack network agent list
  echo "network check exit code: $?"
fi
```

Không bật set -x, không chạy env/printenv OS_PASSWORD và không gửi credentials. Nếu dùng OS_CLOUD/clouds.yaml/profile khác thì chọn rõ một cấu hình xác thực, tránh trộn môi trường. endpoint overrides chỉ áp dụng cho client bastion; không sửa endpoint catalog. Khi port-forward gián đoạn do pod restart, chạy lại đúng phiên đó.

Nếu Service neutron-server không tồn tại, gửi kubectl -n openstack get svc; chưa tạo Service mới. Token PASS chứng minh xác thực Keystone; compute services cần xem state up; network agent list với OVN phải đánh giá theo driver đang dùng. Các tests này chưa thay thế tạo VM/volume.
### 6.5. Kết quả đã xác nhận

Sau khi nạp credentials và endpoint overrides ở 6.4, cả ba lệnh trả exit code 0:

| Kiểm tra | Kết quả xác nhận |
| --- | --- |
| token issue (chỉ in expires) | Keystone xác thực thành công |
| compute service list | nova-compute workerplane-01, conductor và scheduler enabled/up, heartbeat mới |
| network agent list | OVN Controller agents của controlplane-01 và workerplane-01 Alive :-) / State UP |

Kết hợp với RabbitMQ connections và cell1 đã trỏ broker mới, việc chuyển messaging cho Nova/Neutron đã đạt kiểm tra transport/heartbeat/API; Keystone đã đạt authentication. Đây chưa phải kiểm tra tạo VM, kết nối mạng hoặc volume end-to-end.

Danh sách Neutron còn Open vSwitch agent workerplane-01 Alive XXX, State UP. State UP là trạng thái admin enabled, không chứng minh heartbeat còn hoạt động. Với mô hình shared OVN, bản ghi này có thể là agent lịch sử từ phương án triển khai cũ; chưa xác nhận chỉ từ tên. Không cần xóa ngay và không dùng nó để kết luận OVN Controllers lỗi. Nếu dọn sau này, đối chiếu mechanism drivers và workloads OVS agent trước.

Các phần chưa hoàn tất: Cinder vẫn có connections tới broker cũ ở snapshot đã nhận, Glance chưa chuyển endpoint, Helm Nova revision cuối failed/context canceled dù runtime/API đã đạt. Không tuyên bố hoàn tất migration toàn bộ hoặc gỡ broker cũ. MariaDB giữ nguyên. Hạ tầng có chu kỳ boot trước đó, nguyên nhân chưa chốt; theo dõi nếu restart tiếp tục tăng.

Bước triển khai tiếp theo: chuyển Cinder/Glance có kiểm tra render và credential, test volume/image API, sau đó quyết định gỡ broker cũ và hoàn thiện trạng thái release. Octavia/Gateway API triển khai trên nền core API đã kiểm chứng; không thay lại DB/CNI/storage để đồng nhất toàn bộ với Genestack.
## 7. Phạm vi tiếp theo sau RabbitMQ

Giữ MariaDB OpenStack-Helm, không triển khai MariaDB Operator và không bootstrap database mới. Các mẫu MariaDB trong Genestack chỉ là nguồn tham khảo cho đợt sau.

Sau khi Nova ổn định, kiểm tra Cinder/Glance và clients còn dùng broker cũ, hoàn tất nghiệm thu messaging trước khi gỡ broker cũ. Tiếp đó chuẩn bị Octavia và Gateway API theo Genestack với mạng OVN của lab; lựa chọn provider/controller và luồng traffic cần được đối chiếu riêng. Barbican và giao diện LB triển khai theo yêu cầu bài báo cáo. Giữ CNI, storage, database và các dịch vụ đã ổn định.
## 8. Nghiệm thu và gỡ backend cũ

### 8.1. Tiêu chí nghiệm thu

| Lớp kiểm tra | Tiêu chí |
| --- | --- |
| Operators | Controller Ready; CRs reconcile thành công |
| Storage | PVC Bound, mount đúng node/path, filesystem đủ chỗ |
| Helm/workload | Release deployed, Deployments/DaemonSets Ready, jobs cần thiết Complete |
| RabbitMQ | Credentials/permissions đúng; connections và RPC consumers trên broker mới |
| MariaDB | Giữ backend hiện tại; ứng dụng truy vấn DB thành công |
| Nova cells | Cell1 transport và DB connection đúng backend đích |
| Chức năng | Lấy token, liệt kê/tải image, tạo network/VM, tạo/gắn volume theo phạm vi lab |

### 8.2. Gỡ backend cũ và phương án phục hồi

Không gỡ MariaDB. Chỉ gỡ RabbitMQ Helm cũ sau khi toàn bộ clients, jobs và cell mappings đã chuyển, chức năng tích hợp đạt và không còn kết nối cần thiết tới backend cũ. Tên release cần xác nhận bằng `helm list`; không xóa cả namespace openstack hoặc PVC theo nhãn chung.

Giữ chart local, effective values và manifest CR là phần cấu hình bàn giao. Helm rollback có thể trả cấu hình workload, nhưng không tự hoàn tác SQL cell mappings, dữ liệu DB hoặc messages phát sinh trên broker mới. Nếu cần phục hồi, phải điều phối cả endpoints và dữ liệu/mappings; không coi rollback Helm là phục hồi toàn hệ thống.
