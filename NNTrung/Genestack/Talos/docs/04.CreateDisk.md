# Create a Disk    
- **Local Path Provisioner example** uses `diskSelector: match: disk.transport == 'nvme'` with `minSize/maxSize: 200GB` — that's just an example. Since your worker's sdb is a 70GB disk (likely not NVMe/virtio, not necessarily "nvme" transport), you should adjust the `diskSelector` and size to match your actual disk (e.g. `!system_disk` and `minSize/maxSize` around 70GB).
- **Local storage** example uses `minSize/maxSize: 2GB` — for your 10GB control-plane sdb, adjust maxSize accordingly (e.g. up to ~10GB, leaving some margin).
- Also check the linked [disk layout](../../talos/v1.14/configure-your-talos-cluster/storage-and-disk-management/disk-management/layout) doc to confirm you have enough space for the volume you request.

So: attach 70GB sdb to worker for Local Path Provisioner, and 10GB sdb to control-plane for testing Local Storage — then apply the respective `UserVolumeConfig` patches to each node with `talosctl --nodes <ip> patch mc --patch @<file>.yaml`.

### 1. Local Storage on control-plane (sdb 10GB)

Create `local-storage.yaml`:
```yaml
apiVersion: v1alpha1
kind: UserVolumeConfig
name: local-storage
provisioning:
  diskSelector:
    match: "!system_disk"
  minSize: 9GB
  maxSize: 9GB
```
(Keep max slightly under 10GB to leave margin.)

Apply it to the control-plane node:
```bash
talosctl --nodes 192.168.207.137 patch mc --patch @local-storage.yaml
```

Verify:
```bash
talosctl -n 192.168.207.137 get volumestatus u-local-storage
talosctl -n 192.168.207.137 get mountstatus u-local-storage
```
It'll be mounted at `/var/mnt/local-storage` — use that path in a Pod's `hostPath` volume to test.

### 2. Local Path Provisioner on worker (sdb 60GB)

Create `local-path-provisioner.yaml` — since your disk is SCSI, not NVMe, change the selector to match non-system disk instead:
```yaml
apiVersion: v1alpha1
kind: UserVolumeConfig
name: local-path-provisioner
provisioning:
  diskSelector:
    match: "!system_disk"
  minSize: 55GB
  maxSize: 55GB
```

Apply to the worker node:
```bash
talosctl --nodes 192.168.207.139 patch mc --patch @local-path-provisioner.yaml
```

Then deploy Local Path Provisioner via kustomize (pointing config at `/var/mnt/local-path-provisioner`), as shown in the [Local Storage](/kubernetes-guides/csi/local-storage) guide, and apply with `kustomize build | kubectl apply -f -`.

Verify PVC directories with:
```bash
talosctl ls /var/mnt/local-path-provisioner
```

**Note:** if both nodes end up with disks matching `!system_disk`, make sure each `UserVolumeConfig` patch is applied only to the intended node (control-plane vs worker) using `--nodes <ip>`, since the selector alone doesn't restrict which machine it targets.
