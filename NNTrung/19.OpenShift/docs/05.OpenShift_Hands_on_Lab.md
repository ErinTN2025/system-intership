# Lab OpenShift: triển khai, vận hành và quan sát CRI-O

> Kiến thức chuẩn bị: [25 Kiến trúc OpenShift và CRI-O](25.OpenShift_Container_Runtime_Architecture.md), [26 Quy trình vận hành và triển khai](26.OpenShift_Deployment_Operations.md).

## 1. Mục tiêu

Sau bài lab, bạn có thể:

- dùng `oc` đăng nhập và quản lý Project;
- triển khai ứng dụng bằng YAML;
- nối Deployment → Service → Route;
- kiểm tra rollout, scale, config và rollback;
- xử lý Route 503 do Service selector sai;
- quan sát node, kubelet và CRI-O nếu có quyền cluster-admin.

## 2. Môi trường

Chọn một trong hai:

1. **OpenShift Local** trên máy cá nhân: phù hợp nhất nếu muốn làm cả phần CRI-O/node.
2. **Developer Sandbox for Red Hat OpenShift**: phù hợp phần application, thường không cho `oc debug node` hoặc xem Cluster Operators.

Cần cài `oc` tương thích với cluster. Kiểm tra:

```bash
oc version
oc whoami
oc whoami --show-server
```

Không commit token từ lệnh `oc login` vào Git hoặc file lab.

## 3. Lab A — Khám phá cluster

```bash
oc get --raw /version
oc api-resources | grep -E 'routes|imagestreams|buildconfigs|securitycontextconstraints'
oc get nodes -o wide
oc get clusterversion
oc get clusteroperators
```

Trên Sandbox, ba lệnh cuối có thể bị `Forbidden`. Tiếp tục phần application nếu `oc whoami` và tạo Project hoạt động.

Tạo project riêng:

```bash
oc new-project openshift-runtime-lab
oc project openshift-runtime-lab
```

Nếu tài khoản không được tạo Project, dùng Project được cấp sẵn và đặt biến để tránh xóa nhầm:

```bash
export LAB_PROJECT=<PROJECT_DUOC_CAP>
oc project "$LAB_PROJECT"
```

## 4. Lab B — Triển khai ứng dụng bằng manifest

Tạo file `openshift-lab.yaml`:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: hello-config
data:
  LAB_NAME: openshift-runtime
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello
spec:
  replicas: 2
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: hello
  template:
    metadata:
      labels:
        app: hello
        version: v1
    spec:
      containers:
      - name: hello
        image: quay.io/openshift/origin-hello-openshift:latest
        envFrom:
        - configMapRef:
            name: hello-config
        ports:
        - name: http
          containerPort: 8080
        readinessProbe:
          httpGet:
            path: /
            port: http
          initialDelaySeconds: 2
          periodSeconds: 5
        livenessProbe:
          httpGet:
            path: /
            port: http
          initialDelaySeconds: 10
          periodSeconds: 10
        resources:
          requests:
            cpu: 25m
            memory: 32Mi
          limits:
            cpu: 200m
            memory: 128Mi
        securityContext:
          allowPrivilegeEscalation: false
          capabilities:
            drop: [ALL]
          seccompProfile:
            type: RuntimeDefault
---
apiVersion: v1
kind: Service
metadata:
  name: hello
spec:
  selector:
    app: hello
  ports:
  - name: http
    port: 8080
    targetPort: http
---
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: hello
spec:
  to:
    kind: Service
    name: hello
  port:
    targetPort: http
```

Kiểm tra trên API server trước khi tạo:

```bash
oc apply --dry-run=server -f openshift-lab.yaml
oc apply -f openshift-lab.yaml
oc rollout status deployment/hello --timeout=180s
oc get deployment,replicaset,pod,service,route
```

## 5. Lab C — Kiểm tra đường đi của traffic

```bash
oc get pods -l app=hello --show-labels -o wide
oc get service hello -o yaml
oc get endpointslice -l kubernetes.io/service-name=hello
oc get route hello -o wide
oc describe route hello
```

Lấy hostname và gửi request:

```bash
export ROUTE_HOST=$(oc get route hello -o jsonpath='{.spec.host}')
curl -i "http://$ROUTE_HOST"
```

Nếu môi trường tự redirect HTTPS hoặc Route được cấu hình TLS, dùng scheme phù hợp; không dùng `curl -k` như cách xử lý certificate trong production.

Kết quả cần thấy:

- hai Pod Ready;
- EndpointSlice có địa chỉ backend;
- Route có hostname;
- HTTP response đến từ ứng dụng.

## 6. Lab D — Scale và rolling update

```bash
oc scale deployment/hello --replicas=3
oc rollout status deployment/hello
oc get pods -l app=hello -o wide
```

Ghi image hiện tại và revision:

```bash
oc get deployment hello -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
oc rollout history deployment/hello
```

Để quan sát rolling update mà không phụ thuộc một tag image khác, thêm annotation vào Pod template:

```bash
oc patch deployment hello --type=merge -p '{"spec":{"template":{"metadata":{"annotations":{"lab.example.com/revision":"v2"}}}}}'
oc rollout status deployment/hello
oc rollout history deployment/hello
oc get replicasets
```

Rollback:

```bash
oc rollout undo deployment/hello
oc rollout status deployment/hello
```

## 7. Lab E — ConfigMap và Pod lifecycle

```bash
oc patch configmap hello-config --type=merge -p '{"data":{"LAB_NAME":"openshift-runtime-v2"}}'
oc rollout restart deployment/hello
oc rollout status deployment/hello
oc get pods -l app=hello
```

Giải thích: ConfigMap đã đổi nhưng biến môi trường trong process chỉ được đọc khi container khởi động, vì vậy cần tạo Pod mới. Nếu ConfigMap được mount thành volume, nội dung file thường được cập nhật sau một khoảng thời gian, nhưng ứng dụng vẫn phải tự reload file.

## 8. Lab F — Failure injection: Route trả 503

Làm sai selector của Service:

```bash
oc patch service hello --type=merge -p '{"spec":{"selector":{"app":"wrong"}}}'
oc get endpointslice -l kubernetes.io/service-name=hello
curl -i --max-time 10 "http://$ROUTE_HOST"
```

Chẩn đoán:

```bash
oc describe route hello
oc describe service hello
oc get service hello -o jsonpath='{.spec.selector}{"\n"}'
oc get pods --show-labels
oc get endpointslice -l kubernetes.io/service-name=hello
```

Sửa và xác minh:

```bash
oc patch service hello --type=merge -p '{"spec":{"selector":{"app":"hello"}}}'
oc get endpointslice -l kubernetes.io/service-name=hello
curl -i --max-time 10 "http://$ROUTE_HOST"
```

Nguyên nhân là Service không chọn Pod nào, nên router không có backend Ready. Sửa Route hoặc restart Pod không giải quyết selector sai.

## 9. Lab G — Security Context Constraints

Xem ServiceAccount của Pod và SCC đã áp dụng:

```bash
oc get pod -l app=hello -o jsonpath='{range .items[*]}{.metadata.name}{" SA="}{.spec.serviceAccountName}{" SCC="}{.metadata.annotations.openshift\.io/scc}{" UID="}{.spec.containers[0].securityContext.runAsUser}{"\n"}{end}'
oc auth can-i use scc/restricted-v2 --as=system:serviceaccount:$(oc project -q):default
```

Tạo Pod cố ý yêu cầu privileged để quan sát admission từ chối:

```bash
oc run privileged-test \
  --image=busybox:1.36 \
  --restart=Never \
  --overrides='{"spec":{"containers":[{"name":"privileged-test","image":"busybox:1.36","command":["sleep","3600"],"securityContext":{"privileged":true}}]}}'
```

Trên project developer thông thường, request dự kiến bị SCC từ chối. Nếu Pod được tạo, cluster hoặc ServiceAccount đang có quyền SCC rộng hơn; xóa Pod và báo cho người quản trị nếu đó không phải chủ đích:

```bash
oc delete pod privileged-test --ignore-not-found
```

## 10. Lab H — Quan sát CRI-O trên node

> Chỉ thực hiện trên OpenShift Local hoặc cluster lab mà bạn có quyền `cluster-admin`. Không sửa file/node và không chạy trên production.

Chọn node đang chạy Pod:

```bash
export APP_POD=$(oc get pod -l app=hello -o jsonpath='{.items[0].metadata.name}')
export APP_NODE=$(oc get pod "$APP_POD" -o jsonpath='{.spec.nodeName}')
echo "$APP_POD on $APP_NODE"
oc debug node/"$APP_NODE"
```

Trong debug shell:

```bash
chroot /host
systemctl is-active kubelet
systemctl is-active crio
crictl info
crictl pods
crictl ps -a
exit
exit
```

Đối chiếu:

- Pod thấy qua API có sandbox trong `crictl pods` trên đúng node.
- Container có trong `crictl ps`.
- kubelet và CRI-O đang active.
- `crictl` là công cụ debug runtime; không dùng nó để tạo workload do OpenShift quản lý.

## 11. Lab I — Logs và Events

```bash
oc logs deployment/hello --all-containers --tail=100
oc get events --sort-by=.lastTimestamp
oc describe deployment hello
oc describe pod -l app=hello
```

Thực hành phân loại:

- lỗi admission xuất hiện ngay khi API từ chối;
- scheduling/image/volume thường hiện trong Events;
- lỗi process ứng dụng hiện trong logs và container state;
- lỗi Service/Route cần kiểm tra selector, EndpointSlice, port và readiness.

## 14. Bài tập mở rộng

1. Bật edge TLS cho Route bằng certificate lab và kiểm tra bằng `openssl s_client`.
2. Thêm NetworkPolicy default-deny rồi chỉ mở traffic từ ingress controller theo thiết kế cluster.
3. Thêm HPA và tạo tải khi metrics API khả dụng.
4. Thay image bằng digest và so `.status.containerStatuses[].imageID`.
5. Tạo PVC, ghi dữ liệu, xóa/tạo lại Pod rồi xác nhận dữ liệu còn tồn tại.
