# Chuyển RabbitMQ sang Operator cho OpenStack trên Talos

Kết quả trong tài liệu thuộc phiên chuyển đổi RabbitMQ; các revision và tên pod là dữ liệu lịch sử của cụm tham chiếu. Môi trường CLI hiện tại được quản lý bằng admin.sh tại [chương 10](../docs/10-Admin-Environment.md).

Quy trình chuyển đổi backend RabbitMQ — kết quả tham chiếu ngày 07/10/2026. Tiếp nối [05.Openstackhelm.md](05.Openstackhelm.md).

## Quy ước chạy lệnh trong tài liệu

- **Terminal triển khai:** Bash trên bastion, đã chọn đúng kubeconfig/Talos config. Không chạy các khối Bash/Python trong PowerShell hoặc bên trong pod, trừ khi có kubectl exec.
- **Terminal port-forward:** mỗi khối một terminal riêng; lệnh giữ terminal chạy là đúng, không chờ nó kết thúc rồi mới chạy CLI. Terminal CLI là terminal khác.
- **Luồng chuẩn:** chuẩn bị file → render → kiểm tra kết quả → upgrade → kiểm tra runtime. Không chạy nhánh chẩn đoán hoặc restart khi không có lỗi.
- **Khối lệnh:** các dòng mở và đóng EOF hoặc PY xác định nội dung heredoc truyền cho cat/Python. Chúng là thành phần của cú pháp thực thi.
- **Điều kiện chuyển bước:** install/upgrade được thực hiện sau khi render và kiểm tra đạt yêu cầu. Mỗi khối lệnh có phạm vi riêng; tài nguyên đã tạo được kiểm tra bằng show/list trước khi thực hiện lại thao tác create.
- **Mở shell mới:** source virtualenv và file load-admin.sh, gọi load_osh_admin; không mặc định biến OS_* còn tồn tại. Snapshot của cutover được đọc từ file last-prepared.txt sau khi chuẩn bị PASS. File này được tạo bởi quy trình đã tinh gọn, không mặc định tồn tại trên bastion từ lần chạy các lệnh cũ.

| Cú pháp | Mục đích và tác động |
|---|---|
| cat > file <<'EOF' | Ghi/tạo file trên bastion, chưa thay đổi cluster; ghi đè nội dung file đó |
| python3 - <<'PY' | Chạy toàn bộ đoạn Python ngay sau đó; xem mô tả để biết có kubectl apply bên trong hay không |
| helm show values | Tra tên key và defaults của đúng chart |
| helm get values --all | Chụp cấu hình effective của release đang có; có thể chứa credentials |
| helm template ... > file | Render manifest để đọc trước, chưa cài; file output có thể chứa Secret |
| -f A -f B | Hợp nhất values theo thứ tự, B ưu tiên; list bị thay toàn bộ |
| helm upgrade --install | Cài nếu chưa có, cập nhật nếu đã có; chỉ dùng với baseline đúng bước |
| --wait --wait-for-jobs --timeout 15m | Chờ workload/jobs trong phạm vi Helm; không thay thế test chức năng |
| kubectl apply -f file | Tạo/cập nhật tài nguyên trực tiếp, dùng cho manifest CR/Operator trong quy trình |
| kubectl get / describe / logs | Xem trạng thái, events hoặc log; không sửa tài nguyên |
| kubectl rollout restart | Tạo lại pod với cấu hình workload hiện tại, không phải đổi values |

## 1. Mục đích và phạm vi

Chuyển RabbitMQ từ chart server OpenStack-Helm sang mô hình Operator của Genestack. Giữ nguyên MariaDB hiện tại theo phạm vi đã chốt. Các dịch vụ OpenStack tiếp tục được quản lý bằng Helm; giữ các chart local đã sửa cho Talos và shared OVN.

Phạm vi gồm RabbitMQ Cluster Operator, Messaging Topology Operator, cert-manager phục vụ webhook, cấu hình messaging của các dịch vụ và kiểm tra sau chuyển đổi. MariaDB Operator không thuộc đợt triển khai này. Kube-OVN, Rook-Ceph, libvirt, Memcached, Gateway API, Octavia và Barbican được xử lý trong các tài liệu riêng.

Không thay MariaDB hoặc khởi tạo lại database trong quy trình hiện tại. Các dịch vụ đã cài ổn được giữ nguyên, chỉ điều chỉnh phần RabbitMQ cần thiết.

### 1.1. Mô hình quản lý

| Thành phần | Mô hình ở file 05 | Mô hình đích |
| --- | --- | --- |
| RabbitMQ server | Chart OpenStack-Helm tạo StatefulSet | Cluster Operator quản lý `RabbitmqCluster` |
| RabbitMQ user/vhost/quyền | Job `rabbit-init` của chart dịch vụ | Topology Operator quản lý `User`, `Vhost`, `Permission` |
| MariaDB server | Chart OpenStack-Helm | Giữ nguyên |
| Database/user/grant | Cơ chế khởi tạo của OpenStack-Helm | Giữ nguyên |
| Nova/Neutron/Cinder/Glance/Keystone | Helm | Giữ Helm, điều chỉnh backend endpoints và provisioning |

Operator là controller quản lý vòng đời tài nguyên. Controller có thể được cài bằng Helm; khác biệt nằm ở cách quản lý server và tài nguyên ứng dụng qua CR, không nằm ở việc có dùng lệnh Helm hay không.

## 5. Tạo broker và topology OpenStack

### 5.1. RabbitmqCluster cho lab

Tên `rabbitmq-genestack` tránh xung đột Service `rabbitmq` cũ. Một replica, PVC 1 GiB local-path, RAM 1 GiB và node affinity control plane là cấu hình lab; không tương đương HA ba replicas của baseline Genestack. Image `4.3.5-management` giữ cùng phiên bản server với lab cũ. `disk_free_limit.absolute=200MB` là ngưỡng disk alarm, không phải quota PVC.

```bash
cat > ~/osh-lab/operators/rabbitmq-genestack.yaml <<'EOF'
apiVersion: rabbitmq.com/v1beta1
kind: RabbitmqCluster
metadata:
  name: rabbitmq-genestack
  namespace: openstack
spec:
  replicas: 1
  image: rabbitmq:4.3.5-management
  service:
    type: ClusterIP
  persistence:
    storageClassName: local-path
    storage: 1Gi
  resources:
    requests:
      cpu: 250m
      memory: 1Gi
    limits:
      memory: 1Gi
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: kubernetes.io/hostname
                operator: In
                values:
                  - controlplane-01
  tolerations:
    - key: node-role.kubernetes.io/control-plane
      operator: Exists
      effect: NoSchedule
  rabbitmq:
    additionalConfig: |
      disk_free_limit.absolute = 200MB
EOF

kubectl apply -f ~/osh-lab/operators/rabbitmq-genestack.yaml
kubectl -n openstack wait rabbitmqcluster rabbitmq-genestack \
  --for=condition=AllReplicasReady --timeout=300s

kubectl -n openstack get rabbitmqcluster rabbitmq-genestack
kubectl -n openstack get pods,svc,pvc \
  -l app.kubernetes.io/name=rabbitmq-genestack
```

Kiểm tra server:

### 5.2. Credentials adapter và topology

Các Secret `<service>-rabbitmq-user` cũ chỉ có key `RABBITMQ_CONNECTION`. Script đọc connection URI tại bastion, tạo Secret adapter có username/password cho Operator và ba CR cho mỗi dịch vụ. Giữ credentials cũ để ứng dụng không cần đổi mật khẩu. Script này đã chạy thành công cho Nova, Neutron, Cinder, Glance, Keystone. Khi làm lại chỉ chạy trước cutover để tạo credentials/topology; không dùng nó như bước kiểm tra và không tự chạy lại khi đã đổi mật khẩu.

Mỗi vhost mặc định quorum; user service không có administrator tags. Queues RPC/notifications do clients khai báo sau khi kết nối. Đây là lựa chọn của lab, không sao chép các queues runtime hoặc toàn bộ Queue CR mẫu của Genestack.

```bash
python3 - <<'PY'
import base64
import json
import subprocess
from urllib.parse import urlsplit, unquote

namespace = 'openstack'
cluster = 'rabbitmq-genestack'
services = ['nova', 'neutron', 'cinder', 'glance', 'keystone']
objects = []

def resource(kind, name, spec):
    return {'apiVersion': 'rabbitmq.com/v1beta1', 'kind': kind,
            'metadata': {'name': name, 'namespace': namespace,
                         'labels': {'lab-role': 'rabbitmq-genestack-topology'}},
            'spec': spec}

for service in services:
    try:
        result = subprocess.run(
            ['kubectl', '-n', namespace, 'get', 'secret',
             service + '-rabbitmq-user', '-o', 'json'],
            check=True, capture_output=True, text=True)
        secret = json.loads(result.stdout)
        connection = base64.b64decode(
            secret['data']['RABBITMQ_CONNECTION'], validate=True).decode().strip()
        uri = urlsplit(connection)
        username = unquote(uri.username or '')
        password = unquote(uri.password or '')
        vhost = unquote(uri.path[1:]) if uri.path.startswith('/') else ''
        if uri.scheme not in ('rabbit', 'amqp', 'amqps'):
            raise ValueError()
        if username != service or vhost != service or not password:
            raise ValueError()
        if not uri.hostname or ',' in uri.netloc:
            raise ValueError()
    except Exception:
        raise SystemExit('Dung: khong doc/parse duoc Secret cua ' + service
                         + '; KHONG gui connection string/password len chat.')
    name = 'gs-' + service
    objects.append({'apiVersion': 'v1', 'kind': 'Secret',
                    'metadata': {'name': name + '-rabbitmq-credentials',
                                 'namespace': namespace,
                                 'labels': {'rabbitmq.com/topology-operator': 'true'}},
                    'type': 'Opaque',
                    'data': {key: base64.b64encode(value.encode()).decode()
                             for key, value in [('username', username),
                                                ('password', password)]}})
    ref = {'name': cluster, 'namespace': namespace}
    objects.append(resource('Vhost', name + '-vhost',
                            {'name': vhost, 'defaultQueueType': 'quorum',
                             'rabbitmqClusterReference': ref}))
    objects.append(resource('User', name + '-user',
                            {'tags': [], 'importCredentialsSecret':
                             {'name': name + '-rabbitmq-credentials'},
                             'rabbitmqClusterReference': ref}))
    objects.append(resource('Permission', name + '-permission',
                            {'vhost': vhost,
                             'userReference': {'name': name + '-user'},
                             'permissions': {'configure': '.*', 'write': '.*', 'read': '.*'},
                             'rabbitmqClusterReference': ref}))
    print('Da kiem tra credentials/vhost: ' + service + ' (khong hien password)')

result = subprocess.run(['kubectl', 'apply', '-f', '-'],
                        input=json.dumps({'apiVersion': 'v1', 'kind': 'List',
                                          'items': objects}),
                        capture_output=True, text=True)
if result.returncode:
    raise SystemExit('Apply loi, co the da tao mot phan. Kiem tra resources/events; '
                     'khong in stderr/payload Secret. Khong doi endpoint.')
print('Da apply 5 Secrets va 15 topology resources. Can cho reconcile.')
PY
```

```bash
for kind in users.rabbitmq.com vhosts.rabbitmq.com permissions.rabbitmq.com; do
  kubectl -n openstack wait "$kind" \
    -l lab-role=rabbitmq-genestack-topology \

done
kubectl -n openstack exec rabbitmq-genestack-server-0 -c rabbitmq -- rabbitmqctl list_vhosts
kubectl -n openstack exec rabbitmq-genestack-server-0 -c rabbitmq -- rabbitmqctl list_users
```

## 6. Chuyển kết nối OpenStack sang RabbitMQ mới

### 6.1. Override dùng chung

```bash
cat > ~/osh-lab/operators/rabbitmq-cutover/endpoint.yaml <<'EOF'
endpoints:
  oslo_messaging:
    hosts:
      default: rabbitmq-genestack
    host_fqdn_override:
      default: rabbitmq-genestack.openstack.svc.cluster.local
manifests:
  job_rabbit_init: false
  rabbitmq_topology: false
EOF
```

`job_rabbit_init=false` chuyển trách nhiệm provisioning cho Operator. `rabbitmq_topology=false` tránh chart tạo một bộ topology khác với CR `gs-*` đã quản lý riêng. Giữ `secret_rabbitmq=true` trong current values để chart cập nhật Secret connection. Các cờ quorum/durable đã bật trong năm release và được giữ nguyên.

Quy trình mỗi release: lưu current values → render bằng đúng chart → kiểm tra hostname/user/vhost/credentials và jobs → upgrade → kiểm tra rollout/connections/consumers. `helm template` chỉ render, không xác nhận kết nối runtime. Không cần thêm lại override distro khi đã dùng đầy đủ effective values của đúng release.

Không sửa securityContext hoặc đổi cấu hình namespace chỉ để loại bỏ cảnh báo trong đợt chuyển RabbitMQ.

#### C. Chuyển Glance sau Cinder đạt

Mục đích: đổi endpoint Glance, giữ nguyên PVC và cấu hình image. Đọc lại snapshot đã kiểm tra để dùng được khi mở terminal mới. Kết quả cần đạt: revision deployed, API Ready.

```bash
CUTOVER_DIR=$(cat "$HOME/osh-lab/operators/rabbitmq-cutover/last-prepared.txt")
helm upgrade glance ~/osh-lab/charts/glance -n openstack \
  -f "$CUTOVER_DIR/glance-current.yaml" \
  -f ~/osh-lab/operators/rabbitmq-cutover/endpoint.yaml \
  --wait --wait-for-jobs --timeout 15m
```

```bash
helm -n openstack history glance
kubectl -n openstack get pods,jobs,pvc -l application=glance -o wide
kubectl -n openstack exec rabbitmq-genestack-server-0 -c rabbitmq -- \
  rabbitmqctl list_connections user vhost peer_host state
kubectl -n openstack exec rabbitmq-genestack-server-0 -c rabbitmq -- \
  rabbitmqctl list_queues -p glance name type consumers messages
```

Glance có thể chỉ dùng RabbitMQ cho notifications, vì vậy không lấy việc thiếu RPC consumers như Nova/Cinder để kết luận lỗi. Cần kiểm tra cấu hình endpoint và kích hoạt thao tác image để kiểm tra luồng notifications nếu đã bật.

Kết quả Glance đã xác nhận: revision 2 deployed, API trên worker 1/1 Running với restart 0; các jobs mới Complete. Pod API Completed tuổi 9 ngày và rabbit-init tuổi 9 ngày là tài nguyên lịch sử. Không cần dọn để kiểm thử tiếp. Runtime notifier Glance đã xác nhận messagingv2 và hai transport host đúng broker mới; snapshot broker mới chưa có connection user glance và list_queues vhost glance chưa hiển thị queue. Vì Glance có thể chỉ dùng RabbitMQ cho notifications, chưa đủ kết luận lỗi hoặc messaging đã được nghiệm thu; phải kiểm tra driver/transport runtime và thao tác image.

Kiểm tra cấu hình runtime Glance, chỉ in driver và hostname (không in URI/password). Script đọc file chính và thư mục fragments nếu có; nếu có tham số config-file khác trong startup thì cần đối chiếu thêm.

```bash
kubectl -n openstack exec -i deployment/glance-api -c glance-api -- python3 - <<'PY'
import configparser
from pathlib import Path
from urllib.parse import urlsplit
config = configparser.ConfigParser(interpolation=None, strict=False)
files = [Path('/etc/glance/glance-api.conf')]
files += sorted(Path('/etc/glance/glance-api.conf.d').glob('*.conf'))
loaded = config.read([str(p) for p in files])
print('Loaded config files: ' + str(len(loaded)))
assert loaded, 'Khong doc duoc config Glance'
section = 'oslo_messaging_notifications'
print('notification driver=' + config.get(section, 'driver', fallback='(khong khai bao)'))
for name in ['DEFAULT', section]:
    value = config.get(name, 'transport_url', fallback='')
    print(name + ' transport_host=' + str(urlsplit(value).hostname if value else '(khong khai bao)'))
PY
```

Nếu notifier là noop/không bật, không buộc Glance phải có kết nối RabbitMQ hoặc queue. Nếu driver messaging/messagingv2 đang bật, kiểm tra transport host, log lỗi notifier và thao tác image để xác nhận connection; không tự bật notifications chỉ để tạo queue. Việc thiếu queue trong output không ảnh hưởng bằng chứng Helm deployed/API Ready, nhưng chưa chứng minh upload image thành công.

#### D. Kiểm thử tùy chọn — đã bỏ qua trong lần bàn giao này

Giữ port-forward/auth ở mục 6.4; mở thêm hai terminal bastion cho Cinder và Glance nếu chưa có:

```bash
kubectl -n openstack port-forward svc/cinder-api 8776:8776
```

```bash
kubectl -n openstack port-forward svc/glance-api 9292:9292
```

Trong shell đã nạp credentials:

```bash
export OS_VOLUME_API_VERSION=3
export OS_BLOCK_STORAGE_ENDPOINT_OVERRIDE=http://127.0.0.1:8776/v3
export OS_IMAGE_ENDPOINT_OVERRIDE=http://127.0.0.1:9292
timeout 20s openstack volume service list
timeout 20s openstack image list
```

Lặp test tạo volume/image tại mục 12 file 05 với tên mới; không xóa image/volume đang dùng. Tạo volume cần đạt available; attach vào VM đang hoạt động cần in-use nếu nghiệm thu đầy đủ. Việc image list thành công chỉ kiểm tra API, chưa kiểm tra upload/notification. Kết quả chức năng phải được ghi lại trước khi đánh dấu hoàn tất.

Phần kiểm kê sau chỉ dùng trước khi gỡ broker trong lần tái triển khai, không gọi broker đã gỡ ở cụm hiện tại. Kiểm kê tất cả Secret connection và connections của broker cũ; chỉ in hostname, không in URL/password:

```bash
python3 - <<'PY'
import base64
import json
import subprocess
from urllib.parse import urlsplit
result = subprocess.run(['kubectl', '-n', 'openstack', 'get', 'secrets', '-o', 'json'],
                        check=True, capture_output=True, text=True)
for item in json.loads(result.stdout)['items']:
    data = item.get('data', {})
    if 'RABBITMQ_CONNECTION' not in data:
        continue
    try:
        uri = urlsplit(base64.b64decode(data['RABBITMQ_CONNECTION']).decode().strip())
        print(item['metadata']['name'] + ': host=' + str(uri.hostname))
    except Exception:
        print(item['metadata']['name'] + ': khong parse duoc; khong in raw secret')
PY
kubectl -n openstack get pods -l application=rabbitmq -o wide
helm -n openstack history nova
```

Xác định đúng pod broker **cũ** trong output rồi chạy `rabbitmqctl list_connections user vhost peer_host state` trên pod đó. Secret admin/chart cũ có thể còn host rabbitmq; cần phân biệt với clients đang chạy. Zero connections ở một snapshot chưa đủ: kiểm tra thêm workload/cronjob ít chạy và cấu hình runtime. Nova revision failed cũng cần xử lý bằng một lần upgrade có kiểm soát, không chỉnh tay Secret Helm để đổi trạng thái. Chưa gỡ broker trong bước này.

Hiện Cinder/Glance đã chuyển cấu hình; theo quyết định vận hành, đã gỡ broker cũ dù bỏ qua nghiệm thu chức năng cuối. Tiếp đó chuẩn bị Octavia và Gateway API theo Genestack với mạng OVN của lab; lựa chọn provider/controller và luồng traffic cần được đối chiếu riêng. Barbican và giao diện LB triển khai theo yêu cầu bài báo cáo. Giữ CNI, storage, database và các dịch vụ đã ổn định.
## 8. Nghiệm thu và gỡ backend cũ

### 8.1. Tiêu chí nghiệm thu

| Lớp kiểm tra | Tiêu chí |
| --- | --- |
| Operators | Controller Ready; CRs reconcile thành công |
| Storage | PVC Bound, mount đúng node/path, filesystem đủ chỗ |
| Helm/workload | Release deployed, Deployments/DaemonSets Ready, jobs cần thiết Complete |
| RabbitMQ | Credentials/permissions đúng; connections và RPC consumers trên broker mới |
| MariaDB | Giữ backend hiện tại; ứng dụng truy vấn DB thành công |
| Nova cells | Cell1 transport và DB connection đúng backend đích |
| Chức năng | Lấy token, liệt kê/tải image, tạo network/VM, tạo/gắn volume theo phạm vi lab |

### 8.2. Gỡ backend cũ và phương án phục hồi

Không gỡ MariaDB. Chỉ gỡ RabbitMQ Helm cũ sau khi toàn bộ clients, jobs và cell mappings đã chuyển, chức năng tích hợp đạt và không còn kết nối cần thiết tới backend cũ. Tên release cần xác nhận bằng `helm list`; không xóa cả namespace openstack hoặc PVC theo nhãn chung.

Giữ chart local, effective values và manifest CR là phần cấu hình bàn giao. Helm rollback có thể trả cấu hình workload, nhưng không tự hoàn tác SQL cell mappings, dữ liệu DB hoặc messages phát sinh trên broker mới. Nếu cần phục hồi, phải điều phối cả endpoints và dữ liệu/mappings; không coi rollback Helm là phục hồi toàn hệ thống.

### 8.3. Kết quả gỡ broker cũ và dọn PVC còn lại

Theo yêu cầu người vận hành, bỏ qua kiểm thử chức năng/kiểm kê clients cuối và gỡ broker Helm cũ. Không ghi nhận đợt chuyển đổi đã nghiệm thu đầy đủ. Lệnh đã chạy:

```bash
helm uninstall rabbitmq -n openstack --wait --timeout 5m
```

Kết quả: release rabbitmq uninstalled; RabbitmqCluster rabbitmq-genestack AllReplicasReady=True, ReconcileSuccess=True, pod 1/1 Running. PVC persistence-rabbitmq-genestack-server-0 1Gi Bound vẫn còn. Nova revision 6 vẫn failed; runtime/API đã đạt ở kết quả trước nhưng chưa kiểm thử lại sau gỡ broker. Token check mới báo Missing value auth-url vì shell chưa nạp auth theo 6.4; không phải kết quả gọi Keystone thất bại.

PVC cũ được xác định chính xác là rabbitmq-data-rabbitmq-rabbitmq-0, 768Mi, PV pvc-28c44cf9-db09-49f2-887c-d8365bdcb16c. Xóa PVC này là xóa dữ liệu broker cũ; local-path có reclaim policy Delete. Lệnh dọn đã chạy: PVC cũ deleted; PV cũ 768Mi hiện Released với reclaim policy Delete. PVC RabbitMQ Operator, MariaDB và Glance vẫn Bound. Chưa xác nhận PV/thư mục dữ liệu đã được provisioner xóa:

```bash
kubectl -n openstack delete pvc rabbitmq-data-rabbitmq-rabbitmq-0
kubectl -n openstack get pvc
kubectl get pv pvc-28c44cf9-db09-49f2-887c-d8365bdcb16c
```

Kiểm tra tiến trình xóa PV sau khi PVC đã xóa:

```bash
kubectl wait --for=delete pv/pvc-28c44cf9-db09-49f2-887c-d8365bdcb16c --timeout=60s
```

Nếu timeout và PV vẫn tồn tại, kiểm tra:

```bash
kubectl describe pv pvc-28c44cf9-db09-49f2-887c-d8365bdcb16c
kubectl -n local-path-storage logs deployment/local-path-provisioner --since=15m --tail=100
kubectl -n local-path-storage get pods -o wide
```

Không xóa PV hoặc finalizers để làm mất dấu lỗi cleanup. Released nghĩa là claim đã giải phóng, chưa chứng minh thư mục host đã bị xóa. Nếu wait trả NotFound thì PV đã biến mất; không cần chạy lại bước delete PVC. Cleanup PV này không yêu cầu giữ lại broker cũ và không chặn việc chuẩn bị Gateway API.

PV NotFound sau provisioner dọn là kết quả bình thường. Nếu PV vẫn Terminating thì xem events/log provisioner, không gỡ finalizers để bỏ qua. Không xóa PVC persistence-rabbitmq-genestack-server-0, MariaDB hoặc Glance.

Các CRD queues/exchanges/bindings/policies/vhosts/users/permissions.rabbitmq.osh.openstack.org được Helm giữ theo resource policy. Chúng khác CRD *.rabbitmq.com của Operators. Chưa cần xóa CRD OSH: giữ để tránh xóa tài nguyên custom còn tồn tại; không chặn triển khai Gateway API.
