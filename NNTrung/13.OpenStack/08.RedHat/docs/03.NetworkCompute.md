# Network between VM on OpenStack

## 0. Một vài lệnh về mạng
xem MAC của 1 IP:
```bash
sudo ip neigh show 192.168.xx.xx
```
Ví dụ:
```bash 
ping -c 1 192.168.xx.xx

ip neigh show 192.168.xx.xx
```



## 1. Segmentation ID

| Network Type | Segmentation ID là gì? |
|---|---|
| **VLAN** | **VLAN ID/tag**, ví dụ `100`, `200` |
| **VXLAN** | **VNI** — mã định danh mạng VXLAN, không phải VLAN tag |
| **Geneve** | Mã định danh mạng tunnel (**VNI**), không phải VLAN tag |
| **Flat** | Không dùng Segmentation ID |

Network Type = VLAN, Segmentation ID = 120 → network đó dùng VLAN 120 trên physical network tương ứng.

Còn Network Type = VXLAN, Segmentation ID = 120 → đó là VNI 120, không có nghĩa switch vật lý phải trunk VLAN 120.

- Thực hiện check bằng lệnh: `telnet IP port`
  - Network Type
  - Physical Network
  - Segmentation ID

## 2. Check tcpdump

Khi 1 VM bị nghẽn mạng không ra được mạng khác, bạn khoanh vùng được VM bị lỗi sau khi vào check 

- Check xem máy này đưa traffic ra ngoài bằng cách nào có các lệnh sau:
```bash
ip a
ip r
```
- Bạn đứng từ trong 1 máy sau đó cho nó ping liên tục đến 1 IP không tồn tại nó sẽ phải đi hỏi bằng đường ra khỏi switch

- Trong Openstack chú ý nhất là đoạn VLAN và bond
```bash
podman ps 
podman ps -a 
podman ps -a | grep ovs
```

```bash
ovs-vsctl list open .
ovs-vsctl list-ports br-ex
ovs-vsctl list-ports br-int
ovs-vsctl list-ports bs-int | head
ip -d link show 
ip -d link show | grep vlan
```



```bash
tcpdump -n -e -i bond2 arp or icmp and vlan
tcpduml -nne -i bond2 'vlan and (arp or icmp)'
```

Lệnh này dùng để bắt packet trên `bond2` 

| Phần | Ý nghĩa |
|---|---|
| `-n` | Hiện IP dạng số, không phân giải hostname |
| `-e` | Hiện thông tin Ethernet như MAC, VLAN tag nếu có |
| `-i bond2` | Bắt packet trên interface bond2 |
| `arp` | Gói hỏi/đáp địa chỉ MAC |
| `icmp` | Gói ICMP IPv4, thường dùng khi ping |
| `vlan` | Lọc frame có VLAN tag |


- Check tcp dump để biết máy này cắm port switch nào:
```bash
sudo tcpdump -nn -vv -e -s 0 -i bond2 'ethernet proto 0x88cc'
```
