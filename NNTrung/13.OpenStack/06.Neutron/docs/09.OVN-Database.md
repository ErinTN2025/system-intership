## OVSDB Khái niệm

Cả NB DB và SB DB của OVN đều chạy trên nền **OVSDB (Open vSwitch Database Management Protocol)** — một giao thức/engine cơ sở dữ liệu được định nghĩa riêng trong RFC 7047, do dự án Open vSwitch tự phát triển, không dựa trên engine nào có sẵn (không phải SQLite, không phải MongoDB core...).

`ovsdb-server` là daemon (tiến trình) đọc file schema (`.ovsschema` — định dạng JSON) và phục vụ dữ liệu theo schema đó qua giao thức **JSON-RPC**. Mỗi database (Open_vSwitch DB, OVN_Northbound, OVN_Southbound...) là một schema riêng được nạp vào cùng một `ovsdb-server` hoặc các instance khác nhau.

## Đặc điểm cốt lõi

- **Có schema chặt (giống SQL)**: mỗi bảng (table) có các cột (column) với kiểu dữ liệu cố định, được khai báo trước trong file `.ovsschema`. Không giống MongoDB (schema-less/linh hoạt).
- **Kiểu dữ liệu phong phú hơn SQL truyền thống**: một cột không chỉ chứa scalar (string, int, bool) mà còn có thể là `set`, `map`, hoặc tham chiếu UUID tới row ở bảng khác (weak-ref/strong-ref) — gần giống kiểu dữ liệu trong document DB nhưng vẫn nằm trong khuôn khổ schema cố định.
- **Không có ngôn ngữ truy vấn kiểu SQL**: không có `SELECT`, `JOIN` bằng cú pháp SQL. Thao tác qua các operation JSON như `select`, `insert`, `update`, `mutate`, `wait`, gộp trong transaction gửi qua JSON-RPC.
- **Transaction ACID**: hỗ trợ transaction nguyên tử, tương tự RDBMS.
- **Cơ chế Monitor (pub/sub)**: đây là điểm khác biệt lớn nhất so với SQL và MongoDB — client (như `ovn-controller`, `ovn-northd`) có thể "monitor" một bảng/cột và nhận **cập nhật real-time (push notification)** ngay khi dữ liệu thay đổi, thay vì phải poll liên tục. Đây chính là cơ chế OVN dùng để đồng bộ trạng thái mạng gần như tức thời.
- **High Availability bằng Raft**: từ OVS 2.9+/2.11+, `ovsdb-server` hỗ trợ chế độ **clustered database dùng thuật toán đồng thuận Raft** để nhân bản (replicate) dữ liệu giữa nhiều node — tương tự cách MongoDB replica set hay etcd hoạt động, nhưng tự cài đặt riêng, không dùng Raft library ngoài.
- **Nhẹ và chuyên biệt**: `ovsdb-server` không phải database đa dụng — nó được thiết kế chỉ để lưu trạng thái cấu hình mạng (network state), không nhằm phục vụ workload OLTP lớn, không có concept "index" phức tạp hay query optimizer như RDBMS.

## So sánh nhanh

| Đặc điểm | SQL (vd: PostgreSQL) | MongoDB | OVSDB |
|---|---|---|---|
| Schema | Chặt | Linh hoạt (schema-less) | Chặt |
| Model dữ liệu | Bảng/hàng/cột (scalar) | Document (BSON) | Bảng/hàng/cột nhưng cột có thể là set/map/uuid-ref |
| Ngôn ngữ truy vấn | SQL | MQL (query object) | JSON-RPC operations (không có ngôn ngữ query riêng) |
| Giao thức | TCP + wire protocol riêng (hoặc driver) | Wire protocol riêng | JSON-RPC qua TCP/Unix socket |
| Real-time subscribe | Không có sẵn (cần LISTEN/NOTIFY ở Postgres) | Change Streams (khá giống) | Monitor — cơ chế lõi, mặc định |
| HA | Replication (streaming, logical) | Replica set | Raft clustering (từ OVS 2.9+) |
| Mục đích | Đa dụng | Đa dụng | Chuyên biệt cho network state |

## Trong OVN cụ thể

- **NB DB (Northbound)**: lưu ý định cấu hình logic (logical switch, logical router, ACL...) do `ovn-nbctl`/CMS (như Neutron, OpenStack) ghi vào.
- **SB DB (Southbound)**: lưu trạng thái vật lý/runtime (chassis, port binding, flow logic đã dịch...) do `ovn-northd` sinh ra từ NB DB, và `ovn-controller` trên mỗi node đọc để cấu hình OVS thật.

Cả hai đều là hai schema OVSDB độc lập, thường chạy trên hai `ovsdb-server` (hoặc process) riêng biệt, giao tiếp qua cơ chế monitor để mọi thành phần trong cluster luôn đồng bộ trạng thái gần như ngay lập tức — đó là lý do OVN chọn OVSDB thay vì một RDBMS hay MongoDB thông thường.
